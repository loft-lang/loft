# 3D scene-making — extending the method (and why it fits better)

There is no shipped 3D tool yet (the way `sketch/draw.py` is the 2D one). This file
is the transfer plan: what carries over unchanged, what's genuinely new, why 3D is
a *better* fit for this method than 2D, and the honest edge. Build the tool, then
run the same loop.

## Why 3D fits the method better than 2D

Two structural reasons, and they're the whole argument:

1. **3D is specification — and specification is the strength.** A 3D scene is
   geometry, transforms, topology, constraints, parameters. That *is* the metric
   channel: exact, checkable, multi-view verifiable. Far more of the work is the
   measurable kind you're good at, and far less is the perceptual mark-making you're
   weak at.
2. **The renderer does the thing that was the 2D ceiling.** In 2D, modelling *form*
   with value (so a face isn't a flat mask, so a cloud has volume, so shadows fall
   right) was the floor flat fills couldn't reach. In 3D you specify geometry +
   lights + materials and **the renderer computes shading, perspective, occlusion,
   and cast shadows correctly.** The perceptual-modelling you're worst at becomes the
   renderer's physics. The "tool floor" that capped 2D largely disappears.

So the 2D work was the proving ground; 3D is where the method pays off more.

## What transfers unchanged

- **The loop** — freeze intent → compose → block in coarse → measure (cheap) →
  look (sparing) → cold critique → selective fix → iterate. Identical.
- **The metric channel** — now *stronger*: 3D has exact coordinates, dimensions,
  and relationships natively. Encode intent as checks on the scene spec
  (`table.height ~ 0.75m`, `chair.faces(table)`, `prop count == 6`) and on measured
  render facts.
- **The cold-observe critic** (recognition + affect) — run it on rendered views.
  Your recognition is still the human proxy; "does this read as a tavern / feel
  cosy?" judged from the image, not the spec.
- **Coarse-to-fine, selectivity, every-mark-earns-its-place, clarity-has-an-optimum,
  the failure taxonomy, single-pass≠arrival** — all apply directly. (Concealment
  works in 3D too: fog, low light, things off-frame.)

## What's new in 3D (build these)

- **A scene-spec + renderer analog of `draw.py`.** A text scene language (objects,
  transforms, a small library of primitives/meshes, lights, materials, camera) that
  a renderer turns into image(s). Options: a Python tool over a 3D library
  (e.g. a headless renderer / `trimesh` + a rasteriser, or Blender in `--background`
  mode driven by a script — check availability first; neither is a given on a dev box), or — given this is the loft/lavition stack — **a
  scene-spec rendered by the engine itself, plausibly authored in loft** (dogfood:
  the 3D tool as a loft program emitting engine geometry). Keep the same shape as the
  2D tool: edit spec → re-render → cheap text report + image, `check` predicates,
  named objects.
- **Camera as a first-class concern.** Composition in 3D is *also* viewpoint:
  position, look-at, focal length, framing. The composition critic runs on the
  *rendered view*, so it now depends on the camera. Often the fastest "fix" is moving
  the camera, not the geometry.
- **Lights + materials as separate layers.** Mood (the old "value/colour" levers)
  is now light temperature, key/fill, time-of-day, and material response — set these,
  don't paint them. Dusk = a warm low key light + cool ambient, and the renderer does
  the warm/cool for you.
- **Multi-view checking.** Render from several angles (and an orthographic top/side
  for measurement). A model that reads from the hero angle but breaks from the side
  is a caught bug you can't catch in 2D. Cheap text facts (bounding box, dimensions,
  symmetry, poly count) come from the spec directly.

## The sweet spot, and the honest edge

- **Sweet spot: structured / procedural 3D** — environments, architecture, rooms,
  props, low-poly assets, layouts. These are specification-heavy and
  constraint-driven: exactly the strength. If the projects are games, this is the
  target (and parametric/procedural generation amplifies it — describe a rule, check
  the output across seeds).
- **Honest edge: organic realism** — a lifelike character face/body is still hard,
  same as 2D, because it's perception-dense and topology-subtle. Expect *stylized /
  low-poly / blocked-in* to land well and *photoreal organic* to need many passes or
  to stay out of reach. Name that floor up front.
- **Affect is still yours.** "Does the rendered scene *feel* like the intent" is the
  perceptual judgment no measurement gives — unchanged from 2D.

## First moves when a 3D task arrives

1. Confirm the medium fit: structured/props/environment (good) vs organic realism
   (set expectations).
2. If no 3D tool exists yet, **build the minimal scene-spec + renderer first** (the
   `draw.py` analog) — primitives, transform, camera, one light, render to image +
   a text facts report. Don't draw before the loop's instrument exists.
3. Then run the loop: freeze intent (incl. camera + lighting + the feeling), block in
   big masses, check dimensions/relationships as text, render the hero view + an
   ortho view, critique cold, refine across passes.
