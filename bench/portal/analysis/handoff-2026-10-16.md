## After the upgrade — if a tool went missing

Each of these was present before; the upgrade can replace system packages, so check rather
than reinstall.

1. `rustup` (the repo's `rust-toolchain.toml` floats stable and pins the two wasm targets, so
   they install themselves); `cargo install cargo-nextest cargo-sweep cargo-llvm-cov
   cargo-fuzz cargo-expand wasm-pack`.
2. System tools the instruments use: `valgrind` (callgrind), `linux-tools` for `perf` (LBR call
   chains: `perf record --call-graph lbr`; `kernel.perf_event_paranoid` was 2), `binaryen`
   (`wasm-opt`), `python3`, `chromium` (snap), `wasmtime` (`~/.wasmtime`), `gh` (account
   `jjstwerff`: `gh auth login`).
3. In the clone: `make hooks`, `make janitor-install`, `bench/portal/checkout_libs.sh`, then
   `cargo build --release --lib --bin loft` and `make check-rlib`.
4. **Before comparing any timing with the committed portal rows, re-measure**: a new OS,
   glibc and toolchain move both lanes, and the same-machine rule (`bench/README.md`) assumes
   the machine did not change.  Run `make perf-portal` once and commit it as the new baseline.
   A ±10–20 % shift on a row whose emitted Rust did not change is layout, not the change —
   `-C llvm-args=-align-all-functions=6` on both runtimes is how this stretch told them apart.
