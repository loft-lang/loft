## Compiled standard-library bodies — the open arc (option A, owner's choice)

**Why here:** the runner's own data and the guest program's data are two heaps in two C units
(each with its own `static` runtime globals); compiled bodies work on the guest's, so they are
compiled INTO the shim's unit.  Kept deliberately: guest store numbers, `store_memory()` and leak
checks must match the Rust interpreter.

**As built:**
- `src/c/bodies.rs` — `loft --emit-c-bodies <out.c>`: `stdlib_codegen::export_set` (the Rust
  build's own set, 15 functions), `emit_unit_for` over them, the part after `RUNTIME_END`
  without `loft_bind_tables`, one entry per carried body, `loft_body_find(name, len)` (name with
  or without `loft_shared_`; looked up ONCE at image load) and
  `loft_body_call(entry, stack, sp)` (new top, or negative: run the loft body).  Slot ABI:
  arguments below `sp` in push order, a scalar 8 bytes, a text view 16 (`loft_str`), answer at
  the arguments' base (a boolean one byte of its slot).
- Never committed: `c_shim::put_bodies` writes `<loft_bodies.c>` into the shim's staging dir in
  all three build paths (the `-shared` library, the archive, the ship LTO sources) through a
  child `loft --emit-c-bodies`; the shim's identity takes in the binary.  Reason (loft2's
  review): the Unicode tables are the building rustc's.
- `crt.c` ends with `#include <loft_bodies.c>`; `-DLOFT_CRT_NO_BODIES` gives stubs;
  `LOFT_NO_COMPILED_BODIES=1` makes every lookup answer -1 at run time.
- Rules the fragment keeps: a carried body never REPORTS (generation fails on `loft_panic`,
  `loft_assert`, `loft_fault_*`); a body that WRITES a store is not carried until the shim states
  the no-locks / no-threads facts itself (the C writer emits against the unit's facts).
- Guard `tests/crt_bodies.rs`: 12-text matrix, a Unicode sweep (every 7th code point, 158 867,
  against `--interpret` of the same binary), both off-switches.
- Carried: 14 of the 15 — the 7 text predicates, the 4 text answers (`dir`, `basename`,
  `resolve`, `char_slice`), `split`, `split_text` and `vector.join`.  Declined: `File.lines`
  (a record argument: its guard needs a `File` record built in the shim's heap).
- A body that works on records (a reference among its slots) names the unit's type table and
  type numbers.  The fragment keeps its own table (the standard library's types) and such an
  entry runs only once `loft_body_types_ok` found each of them the same in the table the runner
  loaded (`loft_crt_load_types`; the verdict is kept per load, `loft_crt_types_gen`).  Before
  the load, and for another library's types, it answers -1.
- The unit's facts, settled (module header of `src/c/bodies.rs`): `LOFT_NO_LOCKS`,
  `LOFT_NO_THREADS`, `LOFT_FRAMES`, `LOFT_PATH_FOLD` are `#define`s the runtime reads, so they
  are the SHIM's and the bodies' text does not change with them; `Cx::lazy` does change the
  text of a keyed lookup, so a body with one (`OpGetRecord`) is refused.
- The runner's bindings exist: `crt::body_find`, `crt::body_call`, `crt::body_call_dest`
  (`selfhost/crt/src/crt.loft`).
- A text answer is APPENDED to a destination, as the Rust bridge does
  (`extensions::dispatch_shared`).  `loft_body_call_dest(entry, stack, sp, s, r, p)` is the
  `loft_shared_<fn>#dest` form: the runner pops the destination reference, the entry appends
  to the text it names and pushes nothing (new top = the arguments' base).  The plain
  `loft_body_call` appends to the call's own work cell (the first `WorkText` slot, 16 bytes,
  a reference) and pushes its view; `dir` and `basename` have no such cell, so their plain
  form answers -1.  The body's work buffers are the entry's locals.  Slots are judged by
  `native_gate::classify_bridge_attr`, the bridge's own judgment.
- The unit-facts question (loft3's review point 1) does not bind these four: the bodies build
  texts on the C heap and write no store; the one write into guest data is the entry's append,
  which is what `loft_crt_ref_text_append` already does when the loft body returns.

## Gotchas met this session

- The program cache's key ignores uncommitted source: a test that reads emitted code can show a
  stale result until you commit or set `LOFT_NO_CACHE=1`.
- `perf record` here needs `-e cpu_core/cycles/u` and the sandbox off; call graphs are refused
  (`perf_event_paranoid`); use `valgrind --tool=callgrind`, and with `-g -O3 -flto` a build
  `callgrind_annotate` maps instructions to lines of the emitted C.
- A python splice that `s.index("static … name(")` finds the PROTOTYPE first; anchor on the
  definition line that ends with `{`.
- Hand-pricing a runner change: emit with `--native-c --ship --native-emit`, edit, build with
  `cc -std=c99 -O3 -flto rf.c crt.c` (crt.c's includes made absolute), compare like with like.
