## The open arc: the C store port (owner: "do the store port here, they will join it")

Goal: the C lanes under 3.5× the Rust twin; the remaining cost is the C runtime's store work.
The C stream's agent edits `src/c/*` concurrently and joins this branch.

Probe: `target/cstore/sp.loft` — `split` of `make_text(200, 0)` ×20000 (bench 13's helper).
Same answer in both builds; C was 6.38 G instructions against Rust's 1.10 G (5.8×).

**Done — `dc4fc0bd2`:** `loft_bits` (the claims / referenced / removed / lazy / parked bitsets)
keeps a capacity: growth doubles, `loft_bits_clear` keeps the allocation (as `Vec::resize` /
`Vec::clear`).  It used to free on every `loft_st_init` and realloc one word at a time.
6.38 G → 6.19 G instructions, 1.59 G → 1.48 G cycles.  Not yet run: `c_emit`, `c_sweep` on this
commit (the change is a capacity field; run both first thing).

**Next — return-buffer adoption in the C generator, 20 % of `split`.**  `loft_vec_add` copies
each element of the result local's witness store into the caller's `__retbuf` and claims every
text again (`loft_copy_claims`).  The Rust generator removes this with `@FR-R-RetAdopt`; its
analysis `generation::hoist::ret_adopt(data, def_nr) -> Option<RetAdopt {v, vdb, buf, db_tp}>`
is a pure IR read the C generator can call.  The Rust emission to mirror, five points:

1. the init `Set(v, OpGetField(vdb, …))` becomes `v = buf`, minting `buf` when null/rec 0 (the
   C `OpDatabase` form for `db_tp`: `loft_database_wrapper(&buf, size, db_tp)`), else
   `loft_vec_clear_release(…, buf)` — `src/generation/dispatch.rs:44`;
2. `OpDatabase(vdb, …)` emits nothing — `src/generation/ops/misc_ops.rs:52`;
3. `OpSetInt4(vdb, 0, 0)` emits nothing — `src/generation/emit.rs:4675`;
4. inside the `one_buffer_vec_copy` block, `OpClearVector(buf)` and `OpAppendVector(buf, …)`
   emit nothing — `src/generation/emit.rs:3954`, `ops/text_ops.rs:75`;
5. the witness free stays (`loft_free_var` on a null ref is a no-op).

C sites: `src/c/body.rs` `store_operator` (`OpDatabase` ~2930), `OpClearVector` ~3490,
`collection_operator` / `append_vector_op` ~3689, `block_stmt` 1369.  Twins/hoists the Rust side
also excludes (append twins, move pairs, loop buffers) do not exist in C.  Hand-price first: edit
`target/cstore/sp.c` by those five points, compile `-std=c99 -O3`, `perf stat` pinned
(`taskset -c 2`), expect up to −20 %.

**Then, by the cycle profile of `sp` after the bitset fix:** `loft_vec_append` 11 % self,
`loft_st_claim_inner` 7.8 %, `loft_bits_insert` 5 %, `loft_vec_prealloc` 3 %, `loft_set_text`
2.7 %; and ~50 % in the inlined char walk of `split` (`loft_text_char` / `loft_char_len` /

## Gotchas

- The C runtime headers are compiled INTO the `loft` binary: after editing `src/c/*.h`,
  `cargo build --release --bin loft` before `--emit-c`, or the old runtime is emitted.
- `bench/stats.py` and `c_sweep.py` read `target/release/loft`; never rebuild while one runs.
- A rebase onto a squash: build the keep-list from `git show --format=%b -s <squash> | grep '^\* '`
  and replay those commits in `--topo-order`; the interleaved squashed commits make a plain
  range rebase replay all of them (JOINING.md § Rebasing onto a squash).
- `/tmp` is a per-user tmpfs quota; scratch belongs under `target/`.
