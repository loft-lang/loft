## The sweep: 47 routines over 3× (`gap-sweep/`)

`gap-sweep/jobs.tsv` names the kernel each routine's timed loop calls.  To rerun:

```
bench/portal/analysis/gap-sweep/sweep.sh /tmp/gap-sweep      # ~15 min, one routine at a time
python3 bench/portal/analysis/gap-sweep/summary.py /tmp/gap-sweep
python3 bench/portal/analysis/gap-sweep/mechanisms.py /tmp/gap-sweep 30
```

The reports of this run are in `/tmp/gap-sweep/*.txt`, which survives until the next reboot.
`11_par` is left out because its work runs on worker threads and callgrind counts only the calling
thread.  The ratios are by INSTRUCTIONS.  They run above the timed ratio where loft's extra work is
cheap, well-predicted branches (`binary_read` 14.8× by instructions, 4.2× by time) or the twin is
memory-bound (`canvas`).

### Two findings to act on, and one to put to the owner

1. **`strict_stores()` (`src/keys.rs:2818`) runs on every store access in the shipped build.**
   It is the `LOFT_STRICT_STORES` debug switch, read through an atomic plus a branch inside
   `Stores::store`, and it shows in 27 of the 47 routines.  This is the cheapest item in the
   list.  Price it first (`hand_price.sh` with the read removed), then decide how a debug switch
   reaches a release binary.
2. **`offset_in_bounds` runs in 38 of 47 routines**, the store's bounds test on each field
   access, together with `begin_write_inner` (the read-only and init-shadow tests on each write).
   This is the "establish validity once per record or vector, not once per access" class the
   previous reply recommended.  The sweep confirms it is general.
3. **For the owner:** the largest inlined family is the null-integer and checked arithmetic
   (≈ 0.38 twins per routine, in 28 routines).  The owner set that cost aside as "fine for now"
   (a FOCUS, not a decision: `worklist.md`'s focus paragraph).  The sweep says it is now the
   biggest single row, so report it rather than work it.

Single-routine findings the sweep turned up:
- `rand_indices`: the bridge grows the store on every pushed element (`LoftStore::vector_push_long`
  → `Store::resize`, `ffi_resize_pub`, `ffi_reload_pub`: 2.8 twins).
- `pack_u8`: `__tls_get_addr` costs 0.5 twin in the bridge.
- `canvas`: the library fills by doubling (`fi_out += fi_out`) where the twin writes
  `vec![x; n]`.
- `binary_read`: per byte read, the reader's width test, `push_hoisted`, a null-checked add and
  the store tests.
