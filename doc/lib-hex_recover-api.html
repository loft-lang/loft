pub fn orient_k(k: integer, m: integer, o: integer) -> integer

── the 12 orientations, exactly ───────────────────────────────────────────

o is flip * 6 + rot: reflect first (X2, k -> -k), then rotate rot times by 60 degrees (X1, k' = (k-m)/2, m' = (3k+m)/2). Both are exact integer maps on the doubled lattice — the reason a stencil rotates and reflects with no resampling and no drift.

pub fn orient_m(k: integer, m: integer, o: integer) -> integer

The m of a step under orientation o — the companion of orient_k. Walking both is how a shape is compared against all 12 orientations without rebuilding it.

pub fn field_digest(cells: HexSet) -> vector<integer>

THE DIGEST: the lexicographically smallest of the 12 oriented, translated, sorted key vectors. Two cell sets have the same digest **iff** one is an orientation-image of the other — which is exactly "the same stencil", and makes law I visible from the census side.

pub fn digest_eq(a: vector<integer>, b: vector<integer>) -> boolean

Are two digests the same? Compares the shape rather than its spelling, which is what makes a digest usable as an identity.

pub fn digest_text(d: vector<integer>) -> text

A digest as text, for a key, a log line or a diff. The rendering is stable, so two runs that found the same shape write the same string.

pub fn count_digest(cells: HexSet) -> integer

The DEGRADED digest for the second control: cell COUNT alone. A census keyed on a summary instead of the shape collides immediately — both level-1 triangle classes have 3 cells — which is what proves the real digest is carrying the weight.

pub fn turns_cyclic_eq(a: vector<integer>, b: vector<integer>) -> boolean

Are two turn sequences the SAME CLOSED CYCLE, written from a different corner?

A cycle has no distinguished first corner: [2,5,5], [5,5,2] and [5,2,5] are one shape walked from three different starting points. The enumeration cannot know that — it sweeps (h0, turns) — so the census MUST, or it reports a stencil as several and its collisions as law F failures. This is the census discovering a requirement on the canonical text (S6): fixing the winding (C3) is not enough, the starting CORNER has to be fixed too.

pub fn field_exact(cells: HexSet) -> vector<integer>

── THE FAITHFUL DIGEST — a different question, and it must be a different function ─

field_digest above quotients by orientation, because the CENSUS asks "how many distinct SHAPES does this level hold?" and an orientation-image is the same stencil (law I).

LAW F ASKS SOMETHING ELSE: is draw injective — do two distinct models produce two distinct FIELDS? That is about the cells actually written, not about the shape class. A stencil at h0=0 and the same stencil at h0=6 draw genuinely different cells; the shape digest calls them equal, and law F would look violated when nothing is wrong.

So the corpus .f uses THIS one: the field exactly as drawn, no orientation quotient and no translation quotient (every entry is drawn at the same anchor, so position is part of the answer). Using the census digest here reported 17 false law F failures on a 10-entry corpus before the distinction was drawn.

pub fn field_exact_text(cells: HexSet) -> text

The cell set's EXACT digest as text: this shape at this position and orientation. Use it when position matters — two placements of one shape differ here.

pub fn field_norm(cells: HexSet) -> vector<integer>

The TRANSLATION-normalised, orientation-SENSITIVE digest — orientation 0 only.

This is the one rebuild matches on: a recovered stencil must be the same shape at the same heading (h0 is authored, X39), but WHERE it was drawn is placement's business, so position is quotiented and orientation is not. Three digests now, three questions:

field_digest quotient orientation + translation "how many SHAPES?" (census, law I) field_exact quotient nothing "is draw INJECTIVE?" (corpus, law F) field_norm quotient translation only "which STENCIL is this?" (rebuild, R1)

pub fn field_norm_text(cells: HexSet) -> text

The cell set's NORMALISED digest as text: the same shape wherever it sits and however it is turned. Use it to recognise a shape you have seen before.

pub fn form_maxlen(f: Form) -> integer

── THE LEVEL LADDER — the enumeration, parameterised ──────────────────────

A1 fixed every side at length 1. A2 grows len on the same shape, and asks the question the rung ladder poses: **does length alone ever collide?** The enumeration is otherwise identical — 3 sides, all 12 starting headings, every turn triple summing to 12, filtered by law J — so the levels nest: forms_upto(1) is a subset of forms_upto(2).

A form's LEVEL is its longest side, so level n is exactly what forms_upto(n) adds to forms_upto(n-1). That keeps corpus/a1 untouched forever (the never-regenerate rule) while corpus/a2 holds only what is new.

pub fn forms_upto(maxlen: integer) -> vector<Form>

Every admitted 3-sided form with all side lengths in 1..maxlen, canonicalised and deduplicated.

pub fn forms_at_level(n: integer) -> vector<Form>

Only the forms NEW at this level — longest side exactly n.

pub fn turns_reverse_eq(a: vector<integer>, b: vector<integer>) -> boolean

Is b a cyclic shift of a REVERSED — the signature of a MIRROR pair?

The flip is one of the 12 orientations (O = 6 rotations x {id, flip}), and mirroring a turtle walk reverses its turn sequence. At level 1 this never shows: every admitted form has equal sides, so it is achiral and its mirror is just a rotation. Unequal sides make a form and its mirror genuinely different texts — turn 3,5,4 against turn 3,4,5 — that draw mirror-image fields and therefore share a SHAPE digest. That is law **I**, not a law F failure.

pub struct IdxEntry

── INDEXED RECOVERY — draw the candidates ONCE, then look up ──────────────

rebuild_with re-DRAWS every candidate on every lookup: O(N) fills per field, O(N^2) over a corpus — 14161 fills for the 119 entries we hold. Nothing about that is necessary. A candidate's field never changes, so its digest can be computed once and put in a map keyed by the digest. Recovery then becomes a single probe.

WHAT THIS DOES AND DOES NOT BUY, stated plainly because the A3 write-up overstated it:

IT FIXES the per-lookup cost — O(N) fills to build the index, O(1) per recovery afterwards. IT DOES NOT FIX the cost of ENUMERATING the candidate space. Building the index still walks every admissible form once, so the 4-sided house's class (~1.2M proposals, X43) is exactly as far out of reach as before. Reaching THAT needs CONSTRUCTIVE recovery — reading (h0, lens, turns) off the field's own geometry — which is a different piece of work, not a faster table.

LAW F IS CHECKED AT BUILD TIME, ONCE, INSTEAD OF ASSUMED PER LOOKUP. Two candidates sharing a digest would silently overwrite each other in the map, so the build COUNTS such clashes and the gate asserts zero. That is strictly better than the old per-lookup rb_matches count: it is checked once, over the whole space, rather than only where a corpus entry happened to look.

THE FAST PATH: one probe. A hit is an exact R1 answer — the digest IS the field, compared in full, so this is the same exactness the scan gave, not a heuristic narrowing.

A MISS falls back to the scan, and only then, purely to compute the R2 residual. R2 is the exceptional path (content no grammar form draws), so paying O(N) there costs nothing in practice and keeps rho > 0 a real measurement rather than a placeholder.

pub fn hull_keys(cells: HexSet) -> vector<integer>

The convex hull of the filled cells, CCW, corners only — monotone chain in exact integers. Collinear points are dropped (<= 0 pops them), which is what makes long sides come back as one side instead of a run of tiny ones.

pub fn side_heading(dk: integer, dm: integer) -> integer

Which heading, and how many steps, is the vector (dk, dm)? Tries all 12 — a constant — because the heading table's steps are not primitive vectors and a gcd reduction would miss them. Returns the heading, or -1 when the vector is not a whole number of steps in any heading.
