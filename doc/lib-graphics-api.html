pub fn rgba(cr: integer, cg: integer, cb: integer, ca: integer) -> integer

Pack RGBA channels into a single integer using bitwise ops. Layout: bits 24..31 = alpha, 16..23 = red, 8..15 = green, 0..7 = blue. Loft integers are 64-bit signed post-2c, so the packed value fits directly — no widening cast needed. Each channel is MASKED to 8 bits, so an out-of-range argument wraps rather than saturating or being refused.

pub fn rgb(cr: integer, cg: integer, cb: integer) -> integer

Opaque colour: the same pack with alpha 255. rgb(255, 0, 0) is 0xFFFF0000 — NOT the 0xFF0000 a reader reaches for, which has alpha 0.

pub fn color_r(color: integer) -> integer

The channels back out of a packed colour, matching rgba's layout — red, green, blue, then alpha off the high byte.

pub fn color_g(color: integer) -> integer

Green.

pub fn color_b(color: integer) -> integer

Blue.

pub fn color_a(color: integer) -> integer

Alpha. 255 is opaque; a colour written as a bare 0xRRGGBB literal reads 0 here, which is what makes it composite to nothing.

pub struct Canvas { const width: integer, const height: integer, const data: vector<integer> }

A 2D pixel canvas backed by a flat vector of RGBA integers. Pixels are stored row-major: data[y * width + x].

pub fn get_pixel(self: const Canvas, gx: integer, gy: integer) -> integer

Get pixel color at (x, y). Returns 0 if out of bounds — and 0 is a COLOUR the canvas can hold (rgba(0, 0, 0, 0)), so the answer cannot serve as a bounds test. Bound with width/height.

pub fn set_pixel(self: Canvas, sx: integer, sy: integer, color: integer)

Set pixel color at (x, y). No-op if out of bounds. STORES the colour byte for byte, alpha included — it does not composite; blend_pixel does.

pub fn clear(self: Canvas, color: integer)

Fill the entire canvas with a solid color.

pub fn blend(dst: integer, src: integer) -> integer

Alpha-blend src over dst. Both are 0xAARRGGBB packed integers. Uses standard "src over" compositing: out = src * alpha + dst * (1 - alpha).

pub fn blend_pixel(self: Canvas, bx: integer, by: integer, color: integer)

Draw a pixel with alpha blending at (x, y) — the compositing counterpart to set_pixel, and the one a caller reaching for alpha usually meant.

pub fn fill_rect(self: Canvas, rx: integer, ry: integer, rw: integer, rh: integer, color: integer)

Fill a rectangle with a solid color. Clipped to canvas bounds. Like every solid primitive here it STORES the colour (see set_pixel); a rectangle drawn in a half-transparent colour is not a translucent overlay.

pub fn hline(self: Canvas, hx0: integer, hx1: integer, hy: integer, color: integer)

Draw a horizontal line from (x0, y) to (x1, y). Clipped. The end is EXCLUSIVE — [x0, x1) — and a reversed span draws nothing rather than being normalised.

pub fn vline(self: Canvas, vx: integer, vy0: integer, vy1: integer, color: integer)

Draw a vertical line from (x, y0) to (x, y1). Clipped. Exclusive end and no normalisation, exactly like hline.

pub fn draw_rect(self: Canvas, drx: integer, dry: integer, drw: integer, drh: integer, color: integer)

Draw a rectangle outline (1px border). Clipped. Built from four half-open spans, so (x, y, w, h) covers x .. x + w - 1 by y .. y + h - 1.

pub fn draw_line(self: Canvas, lx0: integer, ly0: integer, lx1: integer, ly1: integer, color: integer)

Draw a line from (x0, y0) to (x1, y1) using Bresenham's algorithm. Handles all octants. Each pixel is set (no blending).

pub fn draw_circle(self: Canvas, ccx: integer, ccy: integer, radius: integer, color: integer)

Draw a circle outline using the midpoint algorithm. Center at (cx, cy) with the given radius. Clipped via set_pixel.

pub fn fill_circle(self: Canvas, fcx: integer, fcy: integer, radius: integer, color: integer)

Fill a circle (solid disk). Center at (cx, cy), given radius.

pub fn draw_bezier(self: Canvas, bx0: integer, by0: integer, bx1: integer, by1: integer, bx2: integer, by2: integer, bx3: integer, by3: integer, color: integer)

Draw a cubic Bezier curve from (bx0,by0) to (bx3,by3) with control points (bx1,by1) and (bx2,by2). Uses adaptive subdivision — splits until segments are flat enough, then draws with Bresenham lines. Flatness threshold: max deviation of control points from the chord.

Draw an anti-aliased line using Xiaolin Wu's algorithm. Uses blend_pixel for sub-pixel coverage.

Fill a triangle with vertices (tx0,ty0), (tx1,ty1), (tx2,ty2). Uses flat-top/flat-bottom decomposition with scanline fill.

pub struct Coord { px: integer, py: integer }

A point on the canvas, in pixels.

Exists because a polygon is a LIST of them and fill_triangle's six loose integers do not generalise — six is already the edge of what a caller gets right in order, and a polygon has no fixed count.

NOT called Point: mesh3d::LightType has a Point variant and graphics depends on mesh3d, so the name is taken and the collision is a hard error ("struct 'Point' conflicts with a enumvalue of the same name"). Vertex is mesh3d's too. Reach for Coord in 2-D graphics code and the 3-D names stay where they belong.

pub fn fill_polygon(self: Canvas, pts: const vector<Coord>, color: integer)

Fill a closed polygon under the EVEN-ODD rule.

The polygon closes itself: the last point joins the first, so a triangle is three points and not four. Fewer than three points draws nothing.

Even-odd means a point is inside when a ray from it crosses the outline an odd number of times, so a self-intersecting outline leaves its overlap EMPTY — the classic five-point star is a pentagon-shaped hole with five filled arms. That is a choice, not a bug: the alternative (non-zero winding) fills the middle, and the two disagree on exactly the shapes people draw deliberately.

Matches fill_triangle pixel for pixel on a triangle, which is the reason the row rule below is inclusive rather than the half-open rule a scanline filler usually takes. See the note on polygon_crossings.

pub fn resize_lanczos(self: const Canvas, ow: integer, oh: integer) -> Canvas

Resample this canvas to ow x oh with a Lanczos-3 filter.

Byte-identical to Pillow's Image.resize(..., Image.LANCZOS), which is the point: the .draw corpus renders at 3x and downscales with exactly that, so a renderer that resamples any other way cannot be pixel-compared against it however good it looks (@PLN146 W0 finding 5).

**Alpha is premultiplied across the resample and undone after**, because Pillow defines resize on an image with alpha as convert("RGBa") -> resize -> convert("RGBA"). That is a contract, not an optimisation: resampling straight RGBA lets a transparent texel's colour bleed into its neighbours, and the two disagree on any edge where alpha varies. Both roundings are Pillow's and neither is the obvious one — (v*a + 127)/255 going in, a TRUNCATING divide coming out, and alpha 0 passes its colour through untouched rather than going black.

pub fn resize_bicubic(self: const Canvas, ow: integer, oh: integer) -> Canvas

Resample with a BICUBIC filter — Pillow's Image.resize default.

The default is the reason this exists: resize(size) with no resample= argument is bicubic, and code that builds a small image and enlarges it (a gradient computed at 100x100, say) takes that path without naming it. Read the call site's filter off the ARGUMENT LIST and it looks like there isn't one.

⚠ Bicubic has negative lobes, so an ENLARGEMENT overshoots: a hard 40→200 step upscaled 4x spans 28..212 in Pillow and here alike. That is the filter, not a defect — clamping it away would be the defect.

pub fn save_png(self: const Canvas, path: text) -> boolean

Save canvas as a PNG file. Automatically uses RGBA if any pixel has alpha < 255, otherwise uses RGB. Returns true on success.

The PNG is imaging's (a C shim over lodepng), so it is the same file on every target. A relative path resolves against the program's own directory, as loft's file I/O does. False when the canvas is not whole (fewer pixels than width x height) or the file cannot be written.

pub enum Event { KeyDown { pub key: integer, pub mods: integer, pub repeat: boolean }, KeyUp { pub key: integer, pub mods: integer }, Text { pub content: text }, MouseDown { pub button: integer, pub x: float, pub y: float }, MouseUp { pub button: integer, pub x: float, pub y: float }, MouseMove { pub x: float, pub y: float }, Wheel { pub delta: integer, pub x: float, pub y: float }, TouchBegin { pub id: integer, pub x: float, pub y: float }, TouchMove { pub id: integer, pub x: float, pub y: float }, TouchEnd { pub id: integer, pub x: float, pub y: float }, Resize { pub width: integer, pub height: integer } }

A window's events() answers what arrived since its last poll as a vector of Events, oldest first. Each variant carries its own fields, so nothing is latched and nothing is read through a separate accessor: match ev { KeyDown { key, mods, repeat } => …, Text { content } => … }. key is a KEY_* code (ASCII lower-cased for a character key), mods a MOD_* bitmask, button 1 = left, 2 = right, 4 = middle, delta positive scrolls up, positions are pixels from the window's top-left corner.
