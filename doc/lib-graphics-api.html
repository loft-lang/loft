pub fn rgba(cr: integer, cg: integer, cb: integer, ca: integer) -> integer

Pack RGBA channels into a single integer using bitwise ops. Layout: bits 24..31 = alpha, 16..23 = red, 8..15 = green, 0..7 = blue. Loft integers are 64-bit signed post-2c, so the packed value fits directly — no widening cast needed. Each channel is MASKED to 8 bits, so an out-of-range argument wraps rather than saturating or being refused.

pub fn rgb(cr: integer, cg: integer, cb: integer) -> integer

Opaque colour: the same pack with alpha 255. rgb(255, 0, 0) is 0xFFFF0000 — NOT the 0xFF0000 a reader reaches for, which has alpha 0.

pub fn color_r(color: integer) -> integer

The channels back out of a packed colour, matching rgba's layout — red, green, blue, then alpha off the high byte.

pub fn color_g(color: integer) -> integer

Green.

pub fn color_b(color: integer) -> integer

Blue.

pub fn color_a(color: integer) -> integer

Alpha. 255 is opaque; a colour written as a bare 0xRRGGBB literal reads 0 here, which is what makes it composite to nothing.

pub struct Coord

A point on the canvas, in pixels.

Exists because a polygon is a LIST of them and fill_triangle's six loose integers do not generalise — six is already the edge of what a caller gets right in order, and a polygon has no fixed count.

NOT called Point: mesh3d::LightType has a Point variant and graphics depends on mesh3d, so the name is taken and the collision is a hard error ("struct 'Point' conflicts with a enumvalue of the same name"). Vertex is mesh3d's too. Reach for Coord in 2-D graphics code and the 3-D names stay where they belong.

pub fn fill_polygon(self: Canvas, pts: const vector<Coord>, color: integer)

Fill a closed polygon under the EVEN-ODD rule.

The polygon closes itself: the last point joins the first, so a triangle is three points and not four. Fewer than three points draws nothing.

Even-odd means a point is inside when a ray from it crosses the outline an odd number of times, so a self-intersecting outline leaves its overlap EMPTY — the classic five-point star is a pentagon-shaped hole with five filled arms. That is a choice, not a bug: the alternative (non-zero winding) fills the middle, and the two disagree on exactly the shapes people draw deliberately.

Matches fill_triangle pixel for pixel on a triangle, which is the reason the row rule below is inclusive rather than the half-open rule a scanline filler usually takes. See the note on polygon_crossings.

pub fn resize_lanczos(self: const Canvas, ow: integer, oh: integer) -> Canvas

Resample this canvas to ow x oh with a Lanczos-3 filter.

Byte-identical to Pillow's Image.resize(..., Image.LANCZOS), which is the point: the .draw corpus renders at 3x and downscales with exactly that, so a renderer that resamples any other way cannot be pixel-compared against it however good it looks (@PLN146 W0 finding 5).

**Alpha is premultiplied across the resample and undone after**, because Pillow defines resize on an image with alpha as convert("RGBa") -> resize -> convert("RGBA"). That is a contract, not an optimisation: resampling straight RGBA lets a transparent texel's colour bleed into its neighbours, and the two disagree on any edge where alpha varies. Both roundings are Pillow's and neither is the obvious one — (v*a + 127)/255 going in, a TRUNCATING divide coming out, and alpha 0 passes its colour through untouched rather than going black.

pub fn resize_bicubic(self: const Canvas, ow: integer, oh: integer) -> Canvas

Resample with a BICUBIC filter — Pillow's Image.resize default.

The default is the reason this exists: resize(size) with no resample= argument is bicubic, and code that builds a small image and enlarges it (a gradient computed at 100x100, say) takes that path without naming it. Read the call site's filter off the ARGUMENT LIST and it looks like there isn't one.

⚠ Bicubic has negative lobes, so an ENLARGEMENT overshoots: a hard 40→200 step upscaled 4x spans 28..212 in Pillow and here alike. That is the filter, not a defect — clamping it away would be the defect.

pub fn audio_play(clip: integer, volume: float, looping: boolean = false,

Play a loaded clip. Returns a playback handle, or -1 when it will not play.

volume is 0.0-1.0, looping repeats the clip until it is stopped, pan places it across the stereo field (-1 left, 0 centre, 1 right), and start begins that many seconds in. Everything past volume has a default, so an existing audio_play(clip, 0.8) keeps meaning what it meant.

start skips into the FIRST pass only: a looping clip then repeats whole, which is what a browser's start(when, offset) with loop does.

A handle is never handed out twice. When a clip finishes its slot is reused, but the handle carries which use it belongs to, so an audio_stop on a finished sound stops nothing instead of stopping whatever took its place.

The law is Web Audio's StereoPannerNode, equal-power for a mono clip: a sweep holds its loudness through the middle rather than dipping. A stereo clip is narrowed toward the near side rather than having the far one muted.

pub fn render_frame_no_swap(self: Renderer, sc: const scene::Scene,

Render one frame's 3D passes WITHOUT swapping buffers. Callers that want to draw a 2D overlay between the 3D pass and the swap (e.g. the native Moros editor's panel) use this variant and invoke graphics::gl_swap_buffers() themselves after their overlay renders. Returns false when close requested.

Introduced by Initiative 03 Phase 3b (native moros editor panel overlay). The existing render_frame wrapper below preserves backward compatibility with every current caller.
