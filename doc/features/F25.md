# @F25 — Generics — type variables `<T>`, `<K, V>`, inferred; generic structs

## What it is

A generic function uses a stand-in type, written `<T>`, so one function works for any type. Write "give me the first element of a vector" once, and it works for numbers, for words, or for anything else you pass in.

## How it aids you

Write a piece of logic a single time instead of keeping one near-identical copy per type. Loft fills in the real type for each call, so you get the convenience of one function together with the safety of exact type checking.

The rules to know:

- A function may have several type variables: `fn pair<K, V>(k: K, v: V)`. Loft infers each one from the arguments.
- A struct can be generic too: `struct Box<T> { item: T }`.
- Every type variable must appear in a parameter; otherwise a call has nothing to infer it from, and the function is refused.
- With a bare `T`, a body may assign the value, return it, and store it in a field or a vector. Operators (`a + b`, `a < b`) and formatting (`"{a}"`) need a bound that promises them, such as `<T: Addable>` or `<T: Printable>` (@F26).

## Example

```loft
struct Box<T> { item: T }

fn first<T>(v: vector<T>) -> T {
    v[0]
}
fn wrap<T>(x: T) -> Box<T> {
    Box { item: x }
}
fn main() {
    ints = [10, 20, 30];
    words = ["alpha", "beta", "gamma"];
    println("{first(ints)}");     // 10
    println("{first(words)}");    // alpha
    b = wrap(first(words));
    println("{b.item}");          // alpha
}
```
