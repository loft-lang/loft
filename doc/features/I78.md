# @I78 — Live-reload dispatch

## What it does

The mechanism behind live code reload: it watches the source and, when a function changes, swaps the new version into the already-running program without a restart.

## Where it lives

`src/live_reload.rs`


## In real use

Where this feature carries real work, validated by `check_doc_drift.sh examples`:

Example: @FTR-062 — live reload is one setting, and it is opt-in



## With several definitions of one name

When a name has several definitions chosen by parameter types (multiple dispatch, @PLN162),
live reload keeps every call answering what the CURRENT set of definitions selects: adding a
more specific definition while the program runs takes effect from the next call on, and the old
choice never runs again.  An addition that would make a call ambiguous, or leave a call with no
definition, is refused and the running program is left unchanged; removing a definition or
changing its parameters is refused too.  (`Disp-World` in
`doc/claude/plans/162-multiple-dispatch/RULES.md`; tested by `tests/live_world.rs`.)
