# @I86 — Startup cache & embedded stdlib

## What it does

Makes start-up fast. The standard library is embedded directly into the binary, and a cache lets a later run skip re-parsing and re-compiling that stdlib by restoring the previous result. Without it, every run would pay the full standard-library compile cost before the program even starts.

Editing a program does not throw the stdlib away: a changed program re-parses only itself and takes the stdlib from its cache, and the program's manifest records which stdlib it was built against, so an edited, added or removed stdlib file is never served stale.  An unchanged program run with `--native` goes further — it is recognised from its source files and its compiled binary is started directly, with no parse at all; any change to the program, its libraries, the stdlib or a `LOFT_*` switch the key cannot see falls back to the normal path.

## Where it lives

`src/stdlib_sources.rs` (embedded `default/*.loft` sources), `src/cache.rs` + `src/startup_cache.rs` (the cache)
