# @F97 — `len` vs `size` — logical count vs bytes occupied

## What it is

`len(x)` is a **logical count** and `size(x)` is the **bytes occupied**. For text that is the distinction that matters: `len` counts characters, `size` counts bytes.

## How it aids you

Multi-byte text stops being a trap. When you ask how long a word is, you get characters — what a reader means by length. When you are sizing a buffer or a file record, you ask for `size` and get bytes. Reaching for `len` where bytes were meant is the classic way text handling silently truncates.

## Example

```loft
fn main() {
    s = "café";
    println("len {len(s)} size {size(s)}");   // len 4 size 5
}
```

`é` is one character and two bytes, so the two answers differ — which is the point.

## In real use

Where this feature carries real work, validated by `check_doc_drift.sh examples`:

Example: @STD-001 — `starts_with_at` scans at a BYTE offset, which is `size`'s unit and never `len`'s

Example: @SSH-002 — a terminal's `recv` is a byte stream, so a `len`-bounded loop drops the tail of every multi-byte character
