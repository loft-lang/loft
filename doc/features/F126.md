# @F126 — A store's failure arm — `place = value else { … }` runs when the write did not land

## What it is

An assignment can say what happens when its write does not land.  `place = value else { … }`
runs the block exactly when the place was not there or could not take the value — an index past
the end of a vector, a key the collection does not hold, a field reached through a `null`, a
narrow slot (`u8`, `limit(lo, hi)`) the value does not fit, or a locked store — and never when
the write landed.  The place is written once.  Compound assignments take it too:
`count[k] += 1 else { … }`.

Without an `else`, such a write lands nowhere and the program continues, as it always has; it
logs one warning line (`index_out_of_bounds` for an index, `write_dropped` for a key or a null),
so a dropped write is never silent.  With an `else`, the block is the whole answer and nothing
is logged.

## How it aids you

The question "did that store work?" is answered where the store is written, instead of by
reading the place back — which repeats the path exactly where a mistake in it is likeliest, and
cannot tell a narrow slot's default from a value that was computed.  The block is ordinary code:
it can count the miss, fall back, `continue` a loop or `return`.

A store is never a condition: `if v[1] = 2 { … }` is refused, so the `=`-for-`==` typo cannot
compile.

## Example

```loft
struct Score { name: text, points: integer }

fn main() {
    scores = [10, 20, 30];
    by_name: hash<Score[name]> = [Score { name: "ann", points: 3 }];
    missed = 0;
    scores[1] = 25 else { missed += 1 };              // lands
    scores[7] = 70 else { missed += 1 };              // past the end: the block runs
    by_name["bob"].points += 1 else { missed += 1 };  // no such key: the block runs
    health: u8 = 250;
    health += 10 else { missed += 1 };                // 260 does not fit a u8: the block runs
    println("{scores} missed {missed} health {health}");  // [10,25,30] missed 3 health 0
}
```

The narrow slot still takes its type's default (`0`); the block is how the program learns it.
`if !health { … }` on the very next statement is the older spelling of the same question for a
narrow slot, and still works.
