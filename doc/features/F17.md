# @F17 — Named arguments + default parameter values

## What it is

Pass a function's arguments by name — `connect(host: "db", port: 5432)` — instead of only in order, and give parameters default values so callers can leave them out.

## How it aids you

Call sites read like their own documentation, and you can set just the one option you care about without listing everything before it. Both spellings of a call take names, so `cfg.render(dry: true)` and `render(cfg, dry: true)` are the same call.

Adding a defaulted parameter later does not break the **calls** people already wrote — but it does break the places that use the function as a **value**. A default is not part of the function's type, so `fn(integer) -> integer` no longer matches once a second parameter arrives, however optional it is, and a fn-ref call must pass it explicitly. Grow the signature of something you have handed out as a value and you are making a breaking change.

## Example

```loft
fn connect(host: text, port: integer = 8080, tls: boolean = true) -> text {
    "{host}:{port} tls={tls}"
}
fn main() {
    println(connect("example.com"));              // example.com:8080 tls=true
    println(connect("example.com", tls: false));  // example.com:8080 tls=false
    println(connect(host: "db", port: 5432));     // db:5432 tls=true
}
```

## What a default may be

A default is an expression, not a constant, and it is evaluated **at the call** — once per call, and
not at all when the caller supplies the argument. It can read a parameter declared before it:

```loft
fn window(rows: integer, height: integer = rows * 10) -> integer { height }
window(4)      // 40 — the default reads `rows`
window(4, 7)   // 7  — the default is not evaluated
```
