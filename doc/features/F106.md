# @F106 — Copy and move semantics — when two names share data, and when they do not

## What it is

Three rules decide whether two names share data or hold separate data.

**Naming a whole value copies it.** `b = a` gives `b` its own copy. Writing `b` does not
change `a`. A scalar read out of a record (`k = o.count`) and a tuple element (`t = o.pair`)
are copies too.

**Naming a place inside a value gives you a view of it.** A *place* is a spot inside a
container that holds a value: a field of a record, an element of a vector. A *view* is another
name for that place, so writing the view changes the container. These reads are views:

- a field or element whose type is a struct: `s = o.inner`, or `e = v[0]` on a vector of
  records;
- a nested or indexed read, whatever its type: `c = o.inner.items`, `a = rows[0]`;
- any read off a loop variable or another view: in `for b in list { c = b.items; … }`,
  writing `c` changes the element of `list`.

One read copies instead: a collection field one level inside a value you own. `l = h.list`
gives `l` its own vector.

**Handing a value to a function follows the type, not the bind rule.** A scalar parameter is a
copy. A struct, `value struct` (a struct stored inline, @F95) or collection parameter names
the caller's own value, so a field or element write inside the callee lands in the caller's
record; only replacing the whole binding needs `&` (@F21). A closure capture splits the same
way: a scalar is snapshotted, a store-backed value is shared in both directions (@F22).

A copy costs time and memory, so loft skips it when it safely can:

- **If you never use the source again, loft transfers the value instead of copying it.** This
  is called a *move*. `h = Holder { v: src }` copies when `src` is used later, and moves when
  it is not.
- **Building the value where it belongs avoids the copy entirely** — `h = Holder { v: [1, 2,
  3] }` never makes a second copy, because there was never a first one.

When loft makes a copy that it could have avoided, it tells you, and it names the variable
that kept the value alive.

A view can stop being a view. It lasts only as long as its place does. Four things end the
place, and in each case loft gives the binding its own copy — taken where you wrote it, so it
holds the value you bound — and says so with an advice, because writes through it no longer
reach the container:

- **Removing** from the container. The positions of the remaining elements change, so the view
  can no longer follow its element.
- **Growing** the container (`v += [x]`, an insert, a keyed add). A container that outgrows its
  room moves every element.
- **Writing a key field** through the view, on a keyed collection. The element would end up
  reachable by no key at all.
- **Reassigning the container itself** (`bx = Thing { … }`). The view names a place inside
  `bx`, and giving `bx` a new value leaves nothing for it to point at.

Each event counts wherever it happens: in the same function, or inside a function it calls
with the container. The copy is made only when the view is still used after the event. To keep
writing through, read the view again after the change.

Changing what is IN the place is not the same as ending the place: `o.inner = Box { n: 9 }`
writes into the place `o.inner` already occupies, so a view of it sees the new value and still
writes through.

## How it aids you

You can tell, by reading your own code, whether two names share data — without knowing
anything about the compiler. A whole value is separate; a place inside a value is shared.

You are never charged for a copy silently. When one happens that did not have to, loft names
it and names the variable responsible, so you can decide whether to restructure or leave it.
That turns performance work into something you can see rather than guess at.

## Example

```loft
struct Box { n: integer }
struct Holder { b: Box, tag: integer, list: vector<integer> }

fn main() {
    a = Box { n: 1 };
    b = a;              // whole-value bind — `b` is an independent copy
    b.n = 2;
    println("{a.n} {b.n}");        // 1 2  — writing `b` left `a` alone

    v = [Box { n: 10 }];
    e = v[0];           // a record element — `e` is a view of it
    e.n = 20;
    println("{v[0].n}");           // 20   — writing `e` reached the vector

    h = Holder { b: Box { n: 30 }, tag: 1, list: [5] };
    l = h.list;         // a collection field one level down — a copy
    l[0] = 6;
    println("{h.list[0]} {l[0]}"); // 5 6

    w = h.b;            // a struct field — a view into `h`
    h = Holder { b: Box { n: 40 }, tag: 2, list: [] };   // `h` reassigned — `w`'s place is gone
    // advice: in `main`, `w` was copied out of `h` because `h` is reassigned while `w` is in
    //   use — a view names a place inside `h`, and giving `h` a new value leaves nothing for
    //   it to point at. Writes through `w` no longer reach `h`.
    println("{w.n} {h.b.n}");      // 30 40 — `w` kept the value it was bound to
}
```
