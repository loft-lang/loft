# @F95 — Value structs (`value struct`) — copy semantics, stored inline

## What it is

A `value struct` is a struct with **copy semantics**. Reading one out of a field or a vector element gives you an independent copy, so changing that copy never writes back through the source. Stored inline with no per-element allocation, a `vector<value struct>` costs the same as the raw scalar layout.

## How it aids you

Small geometric things — a point, a colour, a size — behave the way you expect a number to behave when you **bind** one: `q = p.points[0]` is your own copy, and writing it cannot reach back into `p`. You get that without paying for a heap allocation per element, so a vector of a million points is a flat block of memory rather than a million separate records.

The copy is the bind, not the call. **Handing a value struct to a function passes the place itself** — `poke(p.points[0])`, or any `self` method — so the callee's field write lands in your record. Bind it first when you mean to hand over a copy.

## Example

```loft
value struct Point { x: integer, y: integer }

struct Path { points: vector<Point> }

fn main() {
    p = Path { points: [Point { x: 1, y: 2 }, Point { x: 3, y: 4 }] };
    q = p.points[0];    // q is an independent COPY of element 0
    q.x = 99;           // writing it cannot reach back into p
    println("copy {q.x}, source {p.points[0].x}");   // copy 99, source 1
}
```

A value struct is never null: `value struct?` is a compile error, and every one must be initialised. So a fallible constructor cannot answer one *and* signal failure — keep the failure at the underlying type (a `parse` that answers null) and wrap the checked value afterwards.
