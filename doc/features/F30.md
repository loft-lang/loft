# @F30 — `is` variant check (+ field capture)

## What it is

`is` tests whether an enum value is a particular variant — and, in the same step, can pull that variant's own fields out into named values you use right there.

## How it aids you

You check what a value is and reach its data in a single line, with no separate lookup or cast. Whatever you name in the braces is in scope inside the block, and only there.

Without braces, `is` is a plain test that gives a boolean: `found = s is Circle;`.

A cast reaches the variant without a capture. `s as Circle?` gives the `Circle`, or null when `s` holds another variant. A bare `s as Circle` warns (`warning[variant-cast-default]`) and, on a miss, gives a `Circle` with every field at its default. Inside `if s is Circle { … }` the cast `s as Circle` is checked and does not warn.

## Example

```loft
enum Shape {
    Circle { radius: integer },
    Square { side: integer }
}

fn describe(s: Shape) -> text {
    if s is Circle { radius } {
        return "circle of radius {radius}";
    }
    if s is Square { side } {
        return "square of side {side}";
    }
    "unknown"
}

fn main() {
    println(describe(Circle { radius: 5 }));  // circle of radius 5
    println(describe(Square { side: 3 }));    // square of side 3
}
```


## The braces after the variant are always the capture list

That rule is what makes the capture unambiguous, and it has one consequence worth knowing before you write it: the expression form does not parse.

```loft
v = if c is Circle { radius } else { 0 };     // error
```

`{ radius }` is read as the capture list, so a body block has to follow it. The compiler says so: *"`{ radius }` after `is Circle` is the field-capture list, not the body — a block has to follow it"*. For the same reason a capture cannot be followed by `and <condition>`: write the condition as an `if` inside the block. Two spellings do work — write the name twice, or use `match`, which takes captures and IS an expression:

```loft
v = if c is Circle { radius } { radius } else { 0 };            // 5
v = match c { Circle { radius } => radius, Square { side } => side };   // 5
```

A captured name shadows an outer one of the same spelling for the block and hands it back afterwards, and using it after the block is a compile error rather than a stale read — "only there" is enforced, not merely intended.
