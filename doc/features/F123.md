# @F123 — Foreign stores — a mapped file or a library's buffer read in place, a slice of it a view

## Example

```loft
fn main() {
  assert(write_bytes("hello.bin", [104, 101, 108, 108, 111]), "write");
  m = file_map("hello.bin") ?? [];
  assert(len(m) == 5 && m[0] == 104, "the file's bytes, read in place");
  word = m[1..4];
  assert(text_from_bytes(word) == "ell", "a slice is a view of the mapping, not a copy");
  w = m;
  w[0] = 72;
  assert(w[0] == 72 && m[0] == 104, "a bind copies, and the copy is writable");
  println("{text_from_bytes(m)}");
}
```

## What it is

`file_map(path)` gives you a file's bytes as a `vector<u8>` without copying them into memory
first: loft reads them where they lie. A native library can hand over its own buffer the same
way. Such bytes are *foreign*: they belong to the file or the library, not to your program.

`file_map` returns null when the file does not exist, so write `file_map(path) ?? []`.

Every read works as on any vector: the length, an index, a `for` loop, `text_from_bytes`, an
argument to a function or a library. A slice bound to a local (`s = m[lo..hi]`) is a VIEW of
the same bytes, not a copy, and so is a library's whole answer bound to a local.

Foreign bytes are read-only. A write into them — `m[0] = 1`, `m += [2]`, or a write through a
function parameter that received them — is refused. In a development or test run it stops the
program with the advice to copy first; in a production run (`--production`) it is logged and
the write is discarded. To get bytes you can change, copy them:

- a bind copies: `w = m`, and `w` is an ordinary vector;
- storing them into a struct field copies: `h = Holder { b: m }`.

Passing them to a function does not copy, so a function that writes its parameter needs a
copy passed in. The bytes stay valid for as long as any handle or view over them is bound, in
any order of freeing.

## How it aids you

A decoder reads a file, a frame or a library's payload where it lies, and takes each field
as a slice, without first copying the whole thing into a vector and each field out of it
again.  The read-only rule is what makes it safe: nothing can grow or move the
block under a loop that has already taken its base, and a program that needs to change
the bytes says so by copying them.
