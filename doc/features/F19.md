# @F19 — Method dispatch via `self` / `both`

## What it is

A method is a function that belongs to a value. Its first parameter is named `self`, which stands for the value you call it on, and you run it with a dot: `value.method()`.

## How it aids you

Related actions live together with the data they work on, so you write `circle.area()` instead of passing the circle into a loose function. Your code reads left to right like a sentence, and it is easy to find every action a value knows how to do.

## Example

```loft
struct Circle {
    radius: float
}
fn area(self: Circle) -> float {
    3.14159 * self.radius * self.radius
}
fn main() {
    c = Circle { radius: 2.0 };
    println("area = {c.area()}");    // area = 12.56636
}
```


## `self`, `both`, and what actually separates them

The reference has long said `self` is method-only, `both` is both forms, and a plain first-parameter name is free-only. Measured, that is two behaviours rather than three:

| first parameter | `p.f()` | `f(p)` | as a fn-ref (`map(v, f)`) |
|---|---|---|---|
| `self` | yes | **yes** | no |
| `both` | yes | yes | no |
| a plain name | no — refused, naming the free form | yes | yes |

A free call resolves by receiver type, so `f(p)` reaches a `self` method too. What separates `self` and `both` is registration, and it shows in the one place neither reaches: **a method is not a function VALUE**, so it cannot be passed to `map` / `filter` or to a parameter of function type (loft#1008). Wrap it — `map(v, |q| { q.f() })` — or declare the function with a plain first-parameter name and give up the dot.
