# @F127 — Store upgrade — a changed struct converts its stored data, or says why it cannot

## What it is

Store upgrade. When you change a struct whose values are saved in a store, loft converts the old data to the new definition **store to store**, or refuses and says exactly why. An added field takes its default — and a default may be an expression over the stored record (`cents: integer = $.price * 100`). A removed field is dropped, a widened number converted, a changed key or a new index rebuilt by insertion. A narrowed number, a changed kind, or a field removed and another added in one edit (it looks like a rename) is refused with the field and the reason.

`store_load` converts an older store in memory and leaves the file alone; `store_persist_bind` upgrades the file in place and keeps the original as `<path>.old`; `loft layout upgrade <program> <store>` does the same from the command line. A rename is done in two releases: add the new name filled from the old (`name: text = $.label`), drop the old one later.

## How it aids you

You can change your data definitions as freely as your code. Stored data either arrives in the new shape with every value under its own name, or the change is refused before a byte is written — never read raw under the wrong layout and never silently lost.

The compiler warns at the edit, not at the load: `loft layout accept` (and `loft package`, at every release) records the layout your users' stores were written with in `layout.lock`, and a later build that could not upgrade them shows `warning[layout-upgrade-refused]` at the type. A store that skipped releases is carried by an `upgrade(from: Release, old: OldFields, item: T)` routine you write once.

The same converter carries a running program's world across a live rebuild: in `loft --serve` a change the running game could not survive warns on save, and the game keeps running until you apply a build that can.

## Example

```
$ cat v1.loft
struct Item { id: integer, label: text, price: integer }
struct Shop { items: vector<Item> }
fn main() {
  s = Shop { items: [Item { id: 1, label: "pear", price: 3 }, Item { id: 2, label: "fig", price: 12 }] };
  println("saved {store_persist_copy(s, \"shop.store\")}");
}
$ loft v1.loft
saved true

$ cat v2.loft
struct Item {
  id: integer, label: text, price: integer,
  name: text = $.label,                // step 1 of a rename: filled from the old field
  cents: integer = $.price * 100,      // a unit change
  title: text = "{$.id}: {$.label}"    // a combination
}
struct Shop { items: vector<Item> }
fn main() {
  s = Shop {};
  if !store_load(s, "shop.store") { println("not loaded"); return; }
  for it in s.items { println("{it.name} {it.cents} {it.title}") }
}
$ loft v2.loft
pear 300 1: pear
fig 1200 2: fig

$ loft layout upgrade v2.loft shop.store
shop.store: upgraded (the old store is kept as shop.store.old)
  Item.cents added: filled with its default
  Item.name added: filled with its default
  Item.title added: filled with its default

# v3 changes label to an integer: refused, the file untouched
$ loft v3.loft
store_load: refusing shop.store — it was written with a different layout, and it cannot be converted to this program's: Shop.items[].label: changes from text to an integer.
loaded false
```
