# @F125 — Text slicing — `s[a..b]`, `s[a..]`, `s[..b]`, `s[i]` (byte offsets; `char_slice` for characters)

## What it is

`s[a..b]` is the part of a text from byte `a` up to byte `b`, the end excluded; `s[a..]` runs to the end, `s[..b]` starts at the beginning, and a negative bound counts from the end.  `s[i]` is the one character at byte `i`.  The bounds are BYTE offsets — what `size(s)`, `find` and `rfind` count — while `len(s)` counts characters; a bound that lands inside a multi-byte character snaps to it.  For character positions, `s.char_slice(a, b)` counts characters instead.

## How it aids you

Taking a piece of a text needs no function call and no copy loop, and it is spelled the way a vector slice is (@F6), so one habit serves both.

## Example

```loft
fn main() {
    s = "hello, world";
    println("{s[0..5]}");              // hello — bytes 0 up to 5, the end excluded
    println("{s[7..]}");               // world — from byte 7 to the end
    println("{s[..5]} {s[-5..]}");     // hello world — a negative bound counts from the end
    println("{s[0]}");                 // h — one character
    // A bound is a BYTE offset; `char_slice` counts characters instead.
    t = "héllo";                       // `é` is two bytes: len 5, size 6
    println("{t[0..4]} {t.char_slice(0, 4)} {len(t)} {size(t)}");   // hél héll 5 6
}
```

Both ends clamp to the text, and a reversed range gives `""`.  Using a character count as a byte range is the silent mistake: on ASCII the two agree, and on `"héllo"` a range of 4 bytes holds 3 characters.
