# @I63 — Store-resident IR (reader + handle + materializer)

## What it does

Provides a form of the IR that lives directly in the word-addressed store, along with the reader, handle, and materializer used to access it. This lets a program's definitions be persisted and loaded without rebuilding them from source each time.

## Where it lives

`src/data_store.rs`


## In real use

Where this feature carries real work, validated by `check_doc_drift.sh examples`:

Example: @FTR-078 — the same IR graph laid out so a store schema falls out of it: `db.structure` / `enumerate` / `value` / `vector` / `field` for every type, which is the form a definition is persisted in
