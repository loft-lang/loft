# @F99 — Sequence match patterns — alternation, optionals, repetition, capture

## What it is

Match patterns extend to **sequences**: a `match` arm can describe a run of elements — one after another, alternatives, optional parts, repetition — and capture pieces of it while it goes.

## How it aids you

Recognising a shape in a list stops being a hand-written loop with an index and a pile of `if`s. You write the shape you are looking for and name the parts you want out of it, which is the same thing a grammar does — so small parsers, tokenisers and protocol readers read like their specification.

## Example

```loft
enum Tok { Kw { k: integer }, Num { n: integer } }

fn main() {
    v: vector<Tok> = [Kw { k: 1 }, Num { n: 5 }];
    total = match v {
        [Kw { k }, Num { n }] => k + n,
        _ => -1,
    };
    println("matched {total}");   // matched 6
}
```

Sequence patterns compose: `(a)?` makes a part optional, `a | b` alternates, `..rest` binds the tail, and a failed branch reverts the cursor so the next arm sees the original position.
