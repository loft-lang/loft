# @F124 — Operators on a program's own type — `operator compare`, `plus`, `minus`, `times`, `negate`, `divided_by`, `remainder`, `to_<type>`

## What it is

A program's own type gets the operators through `operator` definitions — methods named for the form they back. `operator compare(self: T, other: T) -> Ordering` gives `<`, `<=`, `>` and `>=` (one call each, read against `Less`, `Equal`, `Greater`); `operator plus`, `minus`, `times`, `divided_by` and `remainder` give `+`, `-`, `*`, `/` and `%`, with `+=` and the other compound forms; `operator negate` gives a unary `-x`; `operator to_<type>` gives `x as <Type>`. Each is an ordinary method too: `a.plus(b)` calls the same body as `a + b`.

The right-hand operand may be another type (`operator times(self: Money, n: integer)`), and one name may be defined for several right-hand types; the operand's type picks the definition.

## How it aids you

A value type that adds, scales or orders reads like the numbers it models — `start + span`, `total * 3`, `a < b` — instead of a chain of method calls, and a generic function bounded by `Ordered`, `Addable` or `Numeric` accepts it the way it accepts `integer`.

## Example

```loft
struct Money { cents: integer }

// Each `operator` definition gives the type one form; `a < b` reads `compare`.
operator compare(self: Money, other: Money) -> Ordering { self.cents.compare(other.cents) }
operator plus(self: Money, other: Money) -> Money { Money { cents: self.cents + other.cents } }
operator minus(self: Money, other: Money) -> Money { Money { cents: self.cents - other.cents } }
operator times(self: Money, n: integer) -> Money { Money { cents: self.cents * n } }
operator negate(self: Money) -> Money { Money { cents: 0 - self.cents } }
operator divided_by(self: Money, n: integer) -> Money { Money { cents: self.cents / n ?? 0 } }
operator remainder(self: Money, n: integer) -> Money { Money { cents: self.cents % n ?? 0 } }
operator to_text(self: Money) -> text { "{self.cents / 100}.{self.cents % 100:02}" }

fn main() {
    a = Money { cents: 1250 };
    b = Money { cents: 300 };
    println("{a + b} {a - b} {b * 3} {-b}");     // 15.50 9.50 9.00 -3.00
    println("{a / 4} {a % 7}");                  // 3.12 0.04
    println("{a > b} {a <= b} {a == b}");        // true false false
    a += b;                                      // the compound form comes with `plus`
    println("{a}");                              // 15.50
    // `==` is never redefined: it compares the fields, for every type.
    println("{Money { cents: 5 } == Money { cents: 5 }}");   // true
}
```

`==` and `!=` are not among the forms: they compare the fields of every type, always, and `operator equals` is refused — a comparison of a type's own is a named method (`same_second(self, other)`).  `for e in x` and `"{x}"` have their own forms, `operator next` (@F32) and `operator to_text` (@F105).  `[…]`, `**` and the bit operators stay the built-in types'.  An interface names the same members (`interface Scaled { operator times(self: Self, other: Self) -> Self }`), and the stdlib's `Ordered`, `Addable`, `Subtractable` and `Numeric` are spelled that way.

## In real use

From `time` 0.4.0, the library's `Duration` and `DateTime` define `compare`, `plus`, `minus`, `times` and `negate` this way, so `deadline - now` is a `Duration` and `-span` turns one around.
