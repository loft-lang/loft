# @F96 — `x?` default-fallback operator — discharge a nullable to its type default

## What it is

Postfix `x?` turns a nullable value into a plain one by falling back to that type's **default** when it is null — `0` for a number, `""` for text, `false` for a boolean.

## How it aids you

When any sensible default will do, `x?` says so in one character, instead of spelling out `?? 0` at every use. It binds tightest, so `a.b?` reads the field then discharges it.

## Example

```loft
struct Config { retries: integer?, name: text? }

fn main() {
    c = Config { retries: null, name: null };
    println("retries {c.retries?}");   // retries 0
    println("name [{c.name?}]");       // name []
}
```

A record has a default even when it declares none for its fields: each field takes its own type's zero, so a missing `Point` discharges to `Point { x: 0, y: 0 }` — nested records, vectors and text included. A declared `= default` wins over that zero, which is the reason to write one.

What has no default is a FIELD whose type has none, and that is a plain `enum` with no variant chosen. loft refuses `?` there and names the field: *"record `WithEnum` has no default: field `c: Colour` is an enum with no explicit choice — add `c: Colour = <variant>`, or make it `Colour?`"*.

Use `??` when you want a *specific* fallback instead of the type's default.
