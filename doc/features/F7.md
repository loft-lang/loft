# @F7 — `hash<T[keys]>` keyed collection

## What it is

An INDEX over a set of records, read by a key field. You give it a value for that field and it hands back the matching record straight away, with no searching through a list. A key can be several fields — that is the `[keys]` in `hash<T[keys]>` — and the lookup then takes one value per key: `hash<Cell[x, y]>` is read `grid.cells[1, 2]`.

It is an index rather than a container, and that shows the moment a struct declares two of them over the SAME element type: they are two routes to ONE record set, not two collections. Append through either and both see it, and `len` moves on both. That is a multi-index table for the cost of one extra field declaration — and it is why filling both members of such a group from one literal earns `advice[linked-group-double-fill]`: the records do not divide between them.

## How it aids you

When you need to find "the record with this name" over and over, a hash gives you the answer directly instead of scanning everything each time. You declare which field is the key, so every lookup reads naturally.

A key is unique, so `+=` with a key already present REPLACES that record rather than adding a second one — the count does not move. A lookup that finds nothing answers `null`, and reading a field off that miss stays `null`; nothing is created by asking.

## Example

```loft
struct Person { name: text, age: integer }
struct Directory { people: hash<Person[name]> }
fn main() {
    dir = Directory { };
    dir.people = [ {name: "Ada", age: 36}, {name: "Bo", age: 20} ];
    dir.people += [ {name: "Cy", age: 51} ];
    println("Ada is {dir.people["Ada"].age}, Cy is {dir.people["Cy"].age}");
    // Ada is 36, Cy is 51
    dir.people += [ {name: "Ada", age: 37} ];   // same key — REPLACES, still 3 records
    println("{dir.people["Ada"].age} {dir.people["Zed"] == null}");   // 37 true
}
```
