# @F11 — Tuples — anonymous fixed-arity `(T1, T2, …)`

## What it is

A fixed-size group of values that can each be a different type, written in parentheses like `(3, "three")`. You read the parts by position with `.0`, `.1`, and so on.

## How it aids you

When you want to pass or return a few related values together — a low and a high, or a code and a message — a tuple does it in one step, with no need to define a named type first.

## Example

```loft
fn min_max(a: integer, b: integer) -> (integer, integer) {
    if a <= b { (a, b) } else { (b, a) }
}
fn main() {
    pair: (integer, text) = (3, "three");
    println("{pair.0} = {pair.1}");
    (lo, hi) = min_max(9, 4);
    println("lo={lo} hi={hi}");
    // 3 = three
    // lo=4 hi=9
}
```

## Writing an element, and a reference tuple

An element is assignable like an ordinary variable, and a `&` parameter lets a function write the caller's tuple in place:

```loft
fn swap(p: &(integer, integer)) {
    t = p.0;
    p.0 = p.1;
    p.1 = t;
}

fn main() {
    a = (1, 2);
    swap(a);                       // note: no `&` at the call — the parameter type carries it
    println("{a.0}{a.1}");         // 21
}
```

## Where a `text` element still catches

A tuple holding text reads, interpolates, returns and lives in a vector on both backends, and writing one lands where it is aimed. Two shapes do not work yet, both loudly:

- passing a tuple **variable** with a text element to a function is refused by `--native` at compile time (loft#1005) — the same tuple written as a **literal** argument is fine, as is splitting the elements into separate parameters;
- a `&(text, …)` reference-tuple parameter is an internal compiler error (loft#1006). Use a struct where the elements are text: a struct parameter already names the caller's record, so it writes through with no `&` at all.

Until loft#1004 the write itself was the problem, and silently: `a.0 = "X"` on a `(text, text)` changed `.1`, a write to the last element was discarded, and a write next to a non-text element segfaulted the interpreter.
