# @F102 — Android target — `--native-android`, APK packaging, GL surface and touch input

## What it is

An Android build target. `loft --native-android app.apk prog.loft` cross-compiles the same program you already run on your machine into an installable APK, with an EGL/GLES surface to draw on and touch and keyboard input wired up.

## How it aids you

A game or tool you wrote and tested on your desktop can be installed on a phone without rewriting it for a second platform or hand-assembling the packaging. The program itself is unchanged — the target is a flag, not a fork of your code.

## Example

```bash
loft --native-android app.apk game.loft   # cross-compile and package
adb install -r app.apk                    # install on a connected device
```

Emit a bare `.so` instead of an APK by naming one (`out.so`). `LOFT_ANDROID_TARGET` picks the ABI, defaulting to `aarch64-linux-android`; use `x86_64-linux-android` for an emulator.


A running loft program cannot invoke a command, so the citation below pins the **artefact** instead — the record this tool emits or reads, captured verbatim from a real run, so that a change to the shape a client depends on breaks a test rather than a client. That the command itself runs is guarded by the binary's own Rust suite.
