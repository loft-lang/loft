# @F101 — The build phase — `loft build`, declared targets, zero-config defaults

## What it is

`loft build` builds a project's **targets** — a target being a named shape (native binary, browser page, WASI module) with the toolchain it needs. The built-in targets are implicit, so a project with no configuration at all still builds.

## How it aids you

Producing every artefact your project ships becomes one command rather than a remembered list of flags per platform. Adding a target is a few lines of manifest instead of a script, and the runtime each shape links is built and kept separate for you.

## Example

```bash
loft build              # build the default targets (native, if unset)
loft build html wasi    # build the named targets
loft build path.loft    # a .loft positional overrides the entry point
```

A `[build]` section overrides the built-ins or adds targets of your own:

```toml
[build]
default-targets = ["native", "html"]

[build.target.html]
features = ["random", "png"]
```


A running loft program cannot invoke a command, so the citation below pins the **artefact** instead — the record this tool emits or reads, captured verbatim from a real run, so that a change to the shape a client depends on breaks a test rather than a client. That the command itself runs is guarded by the binary's own Rust suite.
