# @F29 — Pattern matching — enum/scalar/tuple, guards, or-patterns, exhaustiveness

## What it is

`match` picks one branch by comparing a value against a list of patterns, and gives back that branch's result. A pattern can be a specific value, a range, several options at once, a guard, or a catch-all. On an enum, every variant has to be covered.

## How it aids you

One clear choice replaces a long chain of `if` / `else if`, and the chosen result drops straight into a variable instead of being set piece by piece across branches.

"Covered" is enforced two ways, and it is worth knowing which one you are getting. For a CLOSED set — an enum — a missing case is a compile error naming it (`match on Dir is not exhaustive — missing: South`). For an OPEN one — `integer`, `text` — there is no such list to check against, so the arms are enforced by the TYPE instead: a match with no `_` compiles, and a value no arm covers answers `null`. Writing `_` is what makes the result non-nullable.

That `null` is reported only where it meets a non-null context — returning the match into a declared `text` warns, binding it to a local does not. So on an open domain, add `_` (or a `null` arm) unless you mean the fall-through to be an absent value.

## Example

```loft
fn grade(score: integer) -> text {
    match score {
        null     => "absent",
        90..=100 => "A",
        80..90   => "B",
        _        => "other"
    }
}
fn main() {
    println(grade(95));  // A
    println(grade(85));  // B
    println(grade(50));  // other
}
```

`..=` includes its end and `..` does not, and the first arm that matches wins — so `90`
is `"A"` because `90..=100` is listed before `80..90`. The `null` arm catches a genuine
absence, such as reading past the end of a vector. Its price is the in-band sentinel:
the most negative integer IS null, so that one value cannot be told from "absent".

More pattern forms:

- Several options in one arm: `1 | 3 | 5 => "odd"`.
- A **guard** is a condition attached to a pattern: `x if x > 10 => "big"`. The arm is taken only when the pattern matches AND the condition holds.
- A variant pattern binds the variant's fields by name: `Circle { radius } => "radius {radius}"`.
- A tuple pattern matches element by element, with `_` for "any": `(0, _) => "on the y axis"`, `(x, 0) => "on the x axis at {x}"`.

A guarded arm never counts as covering its variant, because its condition may fail. `match d { North if n > 3 => …, South => … }` is refused as *"not exhaustive — missing: North"*; add an unguarded `North` arm or `_`.

```loft
fn size(s: Shape) -> text {
    match s {
        Circle { radius } if radius > 10 => "big circle",
        Circle { radius } => "circle of radius {radius}",
        Square { side } => "square of side {side}"
    }
}
```

For patterns over a sequence — alternation, optional parts, repetition — see @F99.
