# @F24 — Higher-order functions (map / filter / reduce)

## What it is

Three ready-made tools for working with a whole vector at once. `map` makes a new vector by transforming every element, `filter` keeps only the elements that pass a test, and `reduce` combines all the elements into a single value.

## How it aids you

Say what you want done to the list — double each one, keep the even ones, add them all up — instead of writing the loop and the bookkeeping by hand. It is shorter to write, harder to get wrong, and each line reads as one clear step.

## Example

```loft
fn main() {
    nums = [1, 2, 3, 4, 5];
    doubled = map(nums, |x| { x * 2 });
    evens = filter(nums, |x| { x % 2 == 0 });
    total = reduce(nums, 0, |acc, x| { acc + x });
    println("{doubled}");          // [2,4,6,8,10]
    println("{evens}");            // [2,4]
    println("total = {total}");    // total = 15
}
```

## Three more, for a yes/no question

`any` and `all` answer a boolean and stop as soon as they know — `any` at the first element that passes, `all` at the first that fails — and `count_if` counts the ones that pass. They take the same `(vector, predicate)` shape as `filter`, and a predicate must take exactly one argument and answer a boolean.

```loft
fn main() {
    nums = [1, 2, 3, 4, 5];
    limit = 3;
    println("{any(nums, |x| { x > limit })}");        // true
    println("{all(nums, |x| { x > limit })}");        // false
    println("{count_if(nums, |x| { x > limit })}");   // 2
}
```

All six take a named function, a bare lambda, a lambda that CAPTURES (`limit` above), or a fn-ref held in a variable. The three predicate calls used to accept only the first two spellings and discard the call outright for the other two — no loop, no diagnostic, the destination keeping its previous value (loft#1001, fixed).

## The vector is new; the value your callback gets is not

"Makes a new vector" is a promise about the vector, and it holds: the result is its own vector with its own records, so writing into what `map` or `filter` answered never reaches back into the input.

It is not a promise about the value your callback is handed. A `struct` element is a record, and a parameter names that record — the caller's — so a callback that writes to its parameter edits the SOURCE vector:

```loft
struct Row { name: text, n: integer }

fn main() {
    rows = [Row { name: "a", n: 1 }, Row { name: "b", n: 2 }];
    bumped = map(rows, |r| { r.n = 99; r });
    println("{rows[0].n},{rows[1].n}");        // 99,99 — the input moved
    println("{bumped[0].n},{bumped[1].n}");    // 99,99
}
```

A scalar or a text element is copied, so the identical shape leaves the input alone — `map(scal, |x| { x = x * 10; x })` answers `[10,20,30]` and `scal` is still `[1,2,3]`. Which it is depends on the element TYPE, not on how the callback is written, and it is the same in `map`, `filter`, `reduce`, `any`, a comprehension and a plain `for` loop. Build a fresh value in the callback (`Row { name: r.name, n: 99 }`) when the input must not move.

## "Every element" has exceptions today

The loop these six build ends when the element it just fetched reads as *nothing*, and for five element types a real element reads that way — or never does. An `integer`, `float`, `character`, `text` or `struct` element is fine; a `boolean`, a nullable holding `null`, a `vector`, an `enum` or a `value struct` is not (loft#1000):

```loft
fn main() {
    flags = [true, false, true];
    println("{len(map(flags, |b| { b }))}");   // three elements in, answers 1
}
```

An `enum` or `value struct` element does not terminate at all, and a `vector` element answers an empty vector on the interpreter while `--native` refuses to build the program. Until that is fixed, write those five as a `for` statement and build the result by hand — a `for` statement counts its elements and is correct for every element type:

```loft
fn main() {
    flags = [true, false, true];
    out: vector<integer> = [];
    for b in flags { out += [if b { 1 } else { 0 }]; }
    println("{out}");                          // [1,0,1]
}
```
