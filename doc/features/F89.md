# @F89 — Test runner (fn test_*, loft --tests / loft test)

## What it is

loft finds and runs your tests for you: any function named `test_*` is a test. `loft --tests <file>` (or `loft test` in a package) discovers them, runs each, and reports which passed. An `assert(...)` that fails marks the test failed.

## How it aids you

There is no test framework to install and no runner to wire up — name a function `test_something`, put `assert`s in it, and it runs. Tests sit right next to the code they check.

## Example

```
// mymath.loft
fn add(a: integer, b: integer) -> integer { a + b }

fn test_add()  { assert(add(2, 3) == 5); }
fn test_zero() { assert(add(0, 0) == 0); }
```

Run them with `loft --tests mymath.loft` — every `test_*` runs and its pass/fail is reported.


## What the runner actually picks up

Two cases, and which one you are in is decided by the file:

**The file names at least one `test_*`.** Then those are the whole set. A zero-parameter
helper beside them is a helper again, and so is a near-miss name — `testify`, or a function
called exactly `test`, is not a `test_*`:

```loft
fn setup() { println("SETUP RAN"); }
fn test_one() { assert(1 == 1, "ok"); }
```

```
$ loft --tests repro.loft
  ok    repro.loft  (1 fn: test_one)
```

Nothing reports the near-miss: the run says `ok`, having never called it. (A camel-case
`testDouble` cannot catch you out — loft refuses that as a function name.)

**The file names none.** Then arity decides, which is the only reason `--tests` can be
pointed at a plain program at all: every zero-parameter function runs, `main` included,
value-returning ones too, each counted in the total. A function that takes a parameter —
even an unused one — is the only thing skipped, and so today's way to say "not a test"
(loft#1010).

Exit codes are right either way: 1 when something fails, 0 when nothing does.

The count on the per-file line is the cheapest reading of the rule, and a loft file cannot
check it about itself; `tests/test_discovery_rule.rs` asserts both cases and that the
`--native` entry-point generator runs the same set.
