# @F15 — Enum-scoped variant names + context inference

## What it is

When the type is already known — a variable's declared type, a function parameter, a return value — you can write a variant name on its own, like `East`, without repeating the enum name. Loft works out which enum it belongs to from the surrounding context.

## How it aids you

Your code reads cleaner: no need to spell out `Direction.East` every time when it is already clear a `Direction` is expected. It is shorter to write and easier to read, and the compiler still checks the name is a real variant of that enum.

A bare name needs that context. `x = North` has none, so it is refused — even when only one enum has a `North`: *"bare variant 'North' has no type here — qualify it as 'Direction.North', or give the target an enum type"*. Write the qualified name, `x = Direction.North`, or declare the type, `x: Direction = North`. The qualified name is also how you pick one enum when several enums share a variant name.

## Example

```loft
enum Direction { North, East, South, West }
fn turn_around(d: Direction) -> Direction {
    match d { North => South, South => North, East => West, West => East }
}
fn main() {
    d: Direction = East;              // the declared type says which enum
    println("{turn_around(d)}");      // West
    e = Direction.South;              // no context: qualify the name
    println("{turn_around(e)}");      // North
}
```
