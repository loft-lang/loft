# @I72 — Parallel execution runtime

## What it does

Runs loft's parallel constructs (parallel loops and tasks) across multiple threads, coordinating the work and access to the shared store safely. It is the machinery behind the language's `par` features.

One runtime serves both targets: rayon does the scheduling everywhere, and only the source of the threads differs — OS threads natively, Web Worker threads in the browser (which has no `thread::spawn`). A page that cannot get worker threads runs the same `par` sequentially, with the same results.

## Where it lives

`src/parallel.rs` (dispatch over the elements, and the native OS-thread pool), `src/wasm_threads.rs` (the browser half: the host spawns Web Workers against one shared memory and each claims a parked rayon thread)
