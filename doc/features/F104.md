# @F104 — `store_reclaim()` — give a store's unused file space back

## What it is

`store_reclaim(collection)` gives back the free space at the end of a store-rooted collection's store, and answers with the bytes it handed back. For a store bound to a file that is the file shrinking; otherwise it is memory returned to the allocator. Records are never moved, so every reference into the collection stays valid.

## How it aids you

A collection that grew large and then dropped back to a small live set keeps the peak for the rest of the run — the arena grows by 7/3 and never shrinks on its own, so mid-run the size is a rung on a ladder rather than a measure of content. When a live set has dropped *for good*, this hands the difference back. You say when, because only your program knows whether the drop is permanent; a collection that shrinks and grows again would just pay to re-grow.

## Example

```loft
struct Hex { q: integer, r: integer }

fn main() {
    world: hash<Hex[q, r]> = [];
    for i in 0..20000 { world += [Hex { q: i, r: i }] }

    // …the far side of the map is unloaded, for good…
    for i in 10000..20000 { world[i, i] = null }

    freed = store_reclaim(world);
    println("still held: {world.len()}");     // still held: 10000
    println("gave back {freed} bytes");       // a six-figure number here
}
```

You do **not** need this to right-size a file at the end of a run — releasing the collection does that on its own. Reach for it mid-run. Read `store_memory()` first: its `tail%` is exactly what this returns, while its `inner%` is space *between* records, which this does not touch. It returns 0, changing nothing, for a store that is read-only, shares another store's memory, or carries a `store_durable_seal` sidecar.
