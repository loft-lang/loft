# @F128 — Compiled libraries — a `use`d library runs as compiled C under the interpreter

## What it is

A library you `use` runs compiled while your program runs in the interpreter. Each library's loft code is compiled to C — its *unit* — and the interpreter calls into it, the two working on the same data. Each loft release builds the units of every published library for every platform it ships, and `loft install` fetches them, so a machine with no C compiler runs the compiled library too. Where a C compiler is installed, loft builds a library's unit itself the first time the library is used, and keeps it; `loft build-native <package>` builds it ahead of time. A library with no unit for your loft runs interpreted, with the same answers.

## How it aids you

Your script starts at once and stays editable, while the libraries it leans on run at compiled speed — with no Rust toolchain, and for a published library no C compiler either. `LOFT_NO_NATIVE_LIBS=1` runs every library interpreted, the reference a compiled library must answer the same as; `LOFT_HOSTED_VERIFY=1` runs each call into a library both ways and stops at the first that differs. Under `loft debug` the libraries run compiled too.

## Example

```
$ loft install markdown
$ loft my_script.loft                           # markdown runs compiled, my_script.loft interpreted
$ LOFT_NO_NATIVE_LIBS=1 loft my_script.loft     # every library interpreted: the same answers
$ loft build-native ./mylib                     # build a library's unit ahead of time
```
