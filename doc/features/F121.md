# @F121 — Parser in loft (lib/parser.loft) — part of the loft-in-loft front end, not a user library yet

## What it is

`lib/parser.loft` is written in loft and lives in loft's own tree.  It is one of the first pieces of the
loft-in-loft front end — the self-hosting work — where the compiler's own parser (@I58) is rewritten in loft
itself.  **It is not in the registry and is not a supported user library yet**: `loft install`
does not find it, and its interface changes with the front end it is being built for.

What it does today:

It reads loft SOURCE at runtime and tells you whether it is well formed.

`parse(name, source)` is the whole entry point. `name` is the label that appears in the
diagnostics — it need not be a real file. The answer is the NUMBER of errors the source
contained, so `0` means it parsed cleanly; the diagnostics themselves go to the log as the
source is read.

⚠ **@I58 Parser (two-pass recursive descent)** is the parser the compiler uses today, written in
Rust; this file is its loft rewrite, and the compiler does not use it yet.

## Where it lives

`lib/parser.loft`, beside `lib/lexer.loft` — the two front-end pieces of the self-hosting work that exist so far.  The example
below runs from loft's own tree, as the catalogue's example test.

## Example

```loft
use parser;

fn main() {
    // `{{` and `}}` are how a brace survives a loft text literal — the source you
    // hand the parser is ordinary text.
    clean = parser::parse("snippet", "fn add(a: integer, b: integer) -> integer {{ a + b }}");
    println("errors in a good snippet: {clean}");   // errors in a good snippet: 0

    // A malformed snippet is counted, not thrown — the diagnostic goes to the log
    // and the caller decides what to do about it.
    broken = parser::parse("snippet", "fn add(a: integer -> integer {{ a }}");
    println("a malformed one is counted: {broken > 0}");   // a malformed one is counted: true
}
```
