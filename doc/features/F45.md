# @F45 — `sizeof()`

## What it is

`sizeof(...)` tells you how many bytes a type or value takes up when it is packed for storage — for a built-in type, one of your own structs, or a variable.

## How it aids you

Know the storage footprint of your data before you write it out — useful when you save records to a file or reason about how much space a large collection will need.

## Example

```loft
struct Point { x: integer, y: integer }

fn main() {
    println("integer: {sizeof(integer)}");  // integer: 8
    println("u8: {sizeof(u8)}");            // u8: 1
    println("u16: {sizeof(u16)}");          // u16: 2
    println("Point: {sizeof(Point)}");      // Point: 16
}
```


## What the numbers are

Measured, identical on both backends: `integer` 8, `float` 8, `single` 4, `character` 4, `boolean` 1, and `text` 4 — a text is a reference into the store, so `sizeof` gives you the reference, not the characters. A plain enum is 1.

A struct is the sum of its fields with no padding between them: `struct S { a: integer, b: boolean }` is **9**, not 16. That is what makes `sizeof` usable for a file layout — the packed size is the stored size.

A collection is a handle: `sizeof(vector<integer>)` is 4, and a `vector`, `hash` or `index` field adds 4 to its struct, however many elements it holds. `struct H { items: vector<integer>, name: text, pos: hash<S[a]> }` is 12.

`sizeof(x)` on a variable answers the size of the variable's type — the same number as `sizeof` of that type. The one exception is a struct enum (an enum whose variants carry fields): its variants differ in size, so `sizeof(s)` answers the size of the variant `s` holds, worked out at run time.
