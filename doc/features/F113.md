# @F113 — Associated types — an interface names a companion type

## What it is

An interface can name a **companion type** that goes with the implementor, not
only a set of methods. A connection and the cursor it produces are one contract:
`type Rows: Cursor` says "and a row type, which must be a `Cursor`", and a
signature names it as `Self.Rows`.

An implementor writes no `impl` block — satisfaction stays structural — so the
companion is INFERRED from the implementor's own signature: where the interface
wrote `Self.Rows`, the implementor wrote a concrete type, and that is it.

## How it aids you

Without this a cursor has to become state ON the connection, so a connection can
hold only one and the type system cannot say so — a second `select` silently
replaces the first. With it the cursor is its own type, two of them coexist, and
the compiler checks the companion satisfies what the interface promised.

It costs nothing at run time: generics specialise per concrete type, so an
associated type is a compile-time name and the generated code is identical to the
same body written against the concrete types by hand.

## Example

```loft
interface Cursor {
    fn width(self: Self) -> integer
}

interface Source {
    type Rows: Cursor                   // the companion type
    fn open(self: Self) -> Self.Rows    // named in a signature as `Self.<Name>`
}

struct FileRows { w: integer }
struct FileSource { path: text }

fn width(self: FileRows) -> integer { return self.w; }
fn open(self: FileSource) -> FileRows { return FileRows { w: len(self.path) }; }

// The generic holds the companion and calls the bound's methods on it. Two of
// them coexist, which is what a cursor kept ON the connection could never do.
fn total_width<S: Source>(s: S) -> integer {
    a = s.open();
    b = s.open();
    return a.width() + b.width();
}

fn main() {
    println("{total_width(FileSource { path: "abcd" })}");   // 8
}
```

## Rules worth knowing

- **Every position must agree.** The companion is read from the return AND the
  parameters — an implementor whose `open` yields one type while its `feed` takes
  another does not have one companion, and is refused rather than resolved by
  declaration order.
- **The bound is checked per implementor**, and the message names all four
  parties, because three of them are invisible at the call site:
  *"'S1' binds 'Source.Rows' to 'Bad', which does not satisfy the declared bound
  'Cursor': missing width"*.
- **A bound-less `type Held` still binds.** Nothing of the companion's own is
  callable, but the interface that named it can take it back
  (`fn keep(self: Self, h: Self.Held)`).
- The name is a type name and is enforced CamelCase; `Self.<Name>` is spellable
  only inside the declaring interface's body.
