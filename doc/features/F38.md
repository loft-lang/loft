# @F38 — Arithmetic safety — integer overflow/÷0 → null; null propagates through arithmetic

## What it is

When an INTEGER calculation cannot give a real answer — a number grows too big to hold, you divide by zero, or you take a remainder by zero — loft produces `null` for that result and keeps running, instead of crashing.

A null goes on through later arithmetic: `null + 5` and `null * 2` are null too, so one failed step marks every result built on it.

Printed directly, a failed division shows why: `println("{10 / d}")` with `d = 0` prints `null(/0)`. Stored first (`g = 10 / d`), it prints `null`.

**Floats follow IEEE rules instead, by design.** `1.0 / 0.0` is `inf` and `1.0e308 * 10.0` overflows to `inf`; both are *present* values, so `?? fallback` does not fire and the infinity flows on through every later sum and comparison. Two float operations do answer null: `0.0 / 0.0` and a remainder by zero, `x % 0.0`, because NaN is what loft uses for a null float. So whether `x / d ?? 0.0` defends anything depends on whether the numerator happened to be zero. For a float division, test the divisor; `??` is the guard for the integer case.

## How it aids you

One bad integer calculation no longer takes down the whole program. The trouble spot becomes a `null` you can spot and handle (often with `??` to supply a fallback), the way a spreadsheet shows an error in one cell while the rest of the sheet still works.

For a float the cell is not marked, which is what makes the divisor test worth writing: an infinity looks like a number all the way to the file you save.

## Example

```loft
fn main() {
    big: integer = 9_000_000_000_000_000_000;
    total = big + big;          // overflow -> null, no crash
    println("{total}");         // null
    divisor: integer = 0;
    safe = 100 / divisor ?? -1; // divide by zero -> null -> fallback
    println("{safe}");          // -1
    println("done");            // program keeps running
}
```
