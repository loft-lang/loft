# @F32 — Custom iterators via `operator next(self) -> T?`

## What it is

You can make a type of your own work in a `for` loop by giving it a `next` method: it returns the following value each time it is asked, and `null` once there are no more.

## How it aids you

Your own types loop with the same `for x in thing` syntax as the built-in collections, so callers iterate over them without knowing or caring how each value is produced.

The rules to know:

- The loop walks a COPY of the value. After `for x in c { … }`, `c` itself has not moved on, so a second loop starts from the beginning again.
- To consume the value itself, call `next` in a `while` loop: `x = next(c); while x != null { …; x = next(c); }`.
- `x#count` and `x#first` work in such a loop. `x#index` and `rev(c)` do not, because the values have no positions.

## Example

```loft
struct Countdown {
    n: integer
}

// Return the next value, or null when there is nothing left.
operator next(self: Countdown) -> integer? {
    if self.n <= 0 { return null; }
    v = self.n;
    self.n = v - 1;
    v
}

fn main() {
    c = Countdown { n: 3 };
    for x in c {
        println("{x}");   // 3, then 2, then 1
    }
    println("c.n is still {c.n}");   // c.n is still 3 — the loop walked a copy
    x = next(c);
    while x != null {
        x = next(c);      // consumes `c` itself
    }
    println("c.n is now {c.n}");     // c.n is now 0
}
```
