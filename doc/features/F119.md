# @F119 — Store locks (#lock)

## What it is

`#lock` is an attribute on any value that lives in a store — a struct, a vector, a keyed
collection. Set it to `true` and every WRITE to that store panics; reads carry on working.
Set it back to `false` and writes are allowed again. A freshly created store starts unlocked.

The guard is on the STORE, not on the name you happened to lock it through, so it fires
wherever the write is written — including inside a function you passed the value to.

## How it aids you

`const` is the compile-time answer to "this must not change", and it is the one to reach for
first: it costs nothing and it catches the mistake before the program runs.

`#lock` is for the case `const` cannot see — a value that is supposed to hold still for part
of its life and is changing anyway, somewhere you have not found yet. Lock it and the program
stops AT the write, with a stack that names it, instead of carrying a wrong value onward to
wherever it finally looks wrong.

## Example

```loft
struct Counter { value: integer }

fn main() {
    c = Counter { value: 5 };
    println("starts unlocked: {!c#lock}");   // starts unlocked: true

    c#lock = true;
    println("locked: {c#lock}");             // locked: true
    println("still readable: {c.value}");    // still readable: 5
    // `c.value = 6` would panic here, and so would a write inside any function
    // handed `c` — the guard travels with the store.

    c#lock = false;                          // lift the guard
    c.value = 6;
    println("written once unlocked: {c.value}");   // written once unlocked: 6
}
```
