# @F39 — Math & trigonometry library

## What it is

A set of ready-made number functions: absolute value, the smaller or larger of two values (`min` / `max`), square root, powers (`pow`), the trigonometry functions (`sin` / `cos` / `tan`) and their inverses (`asin` / `acos` / `atan`), rounding (`floor` / `ceil` / `round`), logarithms (`log(value, base)` and the natural `ln`), and the constant `PI`. Each has a `float` and a `single` form.

`round` goes half away from zero: `round(2.5)` is 3 and `round(-2.5)` is -3.

## How it aids you

Reach for the operation you need by name instead of spelling out the formula by hand — one call for a square root, a power, or an angle — so numeric code stays short and reads the way you would say it out loud.

## Example

```loft
fn main() {
    println("abs: {abs(-7)}");            // abs: 7
    println("min/max: {min(3, 9)} {max(3, 9)}");  // min/max: 3 9
    println("sqrt: {sqrt(144.0)}");       // sqrt: 12
    println("pow: {pow(2.0, 10.0)}");     // pow: 1024
    println("cos(0): {cos(0.0)}");        // cos(0): 1
    println("pi: {PI}");                  // pi: 3.141592653589793
}
```

## Six of them can answer null

A domain has holes, and loft spells a hole as null rather than a crash or a NaN you have to test for — NaN IS the null float. So **`sqrt`, `pow`, `log`, `ln`, `asin` and `acos` are declared `float?`** while `abs`, `sin`, `cos`, `tan`, `atan`, `floor`, `ceil`, `round`, `min` and `max` are total and answer a plain `float`.

An INFINITY is not a hole, and that is the pair to get right: `log(0.0, base)` is negative infinity and `1.0 / 0.0` is positive infinity, so `??` never fires on either, while `sqrt(-1.0)` and `asin(2.0)` are null and it does.

Nothing above shows this, because every argument in it is a LITERAL and a literal folds — `sqrt(144.0)` is statically 12.0, so it binds to a plain `float`. The same call on a variable does not:

```loft
x: float = sqrt(144.0);          // fine — folded to a non-null constant
v = 144.0;
x: float = sqrt(v);              // refused: cannot change type from float to float?
y = sqrt(v);                     // fine — y is `float?`
z: float = sqrt(v) ?? 0.0;       // fine — discharged
```

Passing one into a non-null parameter compiles and warns, and the value really does arrive null: *"a nullable `float?` is stored into parameter 1 of `f` of the non-null type `float` — it becomes null there"*.
