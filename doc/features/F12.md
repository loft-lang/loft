# @F12 — Struct records — fields, `= default`, `computed`, `limit`/`not null`/`assert`

## What it is

A named type that groups related values together as fields. Create one by naming its fields; read a field with a dot. Fields can carry modifiers, and they are not all the same kind of thing — some are checked by the compiler, and one at run time:

- **`const`** — set once at construction; assigning it afterwards is a compile error.
- **`= default`** — the value to use when a literal leaves the field out. Without one, an omitted field takes its type's default: zero, or the bound nearest zero when zero is out of range. A literal that names some fields and leaves such a field out gets `advice[omitted-field-zero]`, because nothing in the declaration chose that value.
- **`computed(expr)`** — worked out on every access and never stored, with `$` naming the record: `area: float computed(3.14159 * $.radius * $.radius)` follows `radius` for free and costs no space.
- **`assert(...)`** — a rule loft enforces at RUN time: a write that breaks it stops the program with `field constraint failed on <Type>.<field>`.
- **`limit(lo, hi)`** — a range the compiler enforces, like a narrow type (`u8` *is* `integer limit(0, 255)`). A store that may not fit is refused at compile time: *"cannot implicitly narrow integer to integer(0, 1000000)"*. Give it a fallback (`a.balance = n ?? 0`) or make the value provably fit. A compound step past the range (`a.balance += 10` at the top) takes the type's default — zero, or the bound nearest zero, so `limit(1000, 1100)` gives 1000 — and gets `advice[narrow-fallback]`. Write `(a.balance + 10) ?? d` to choose that value yourself.
- **`not null`** — deprecated and does nothing; a type is non-null by default and loft says so when it sees one.

## How it aids you

Instead of juggling several loose variables that belong together, you keep them in one named thing — easier to pass around, and the field names say what each value means. `const`, `limit(...)`, `assert(...)` and `computed(...)` put the rule next to the data it governs, so an identifier that must never change, a value that must stay in range, or a number derived from the others says so where it is declared rather than in every function that touches it.

## Example

```loft
struct Account {
    const id: integer,
    name: text = "unnamed",
    balance: integer limit(0, 1000000),
}

fn main() {
    a = Account { id: 7, balance: 250 };
    println("{a.id} {a.name} {a.balance}");   // 7 unnamed 250
    a.balance = 300;                          // an ordinary field changes
    println("balance {a.balance}");           // balance 300
}
```

`name` was omitted at construction, so it took its default. Assigning `a.id` is a compile error — a `const` field is fixed once the record exists. `a.balance = n` with a plain `integer` `n` is a compile error too, because `n` may not fit `limit(0, 1000000)`; write `a.balance = n ?? 0`.
