## Open questions for the owner

- **`view-copied` on a view nothing writes through.**  `compound`'s `vt = inner` and
  `match_expr`'s `result = b.tp` earn the advice although neither view is ever written
  through, so neither fix line applies and the copy is exactly what the code wants.
  `(H-Materialise)` says "the author is told" unconditionally, so silencing it is a rule
  change, not a fix.
- **Its location** for a loop-carried reassignment: `parse_block`'s advice points at the last
  statement of the loop body (column 0), not at the `x = …` that reassigns the container on
  the next pass.  Not reproduced in a small probe yet.

- **`api-redoes-per-field` on a consumer that is no reader.**  `el_vars::rebind_witness`
  answers `work_ref(v, tp(v, p))`: the lint reads `work_ref` as "one value of" the `TypeT`
  `tp` builds, but `work_ref` MUTATES `v` (mints a variable), so three calls are three mints
  whatever the caller holds, and the cure ("answer the built record once") does not apply.
  `int_range`'s long-standing advice is the same lint over `tp(vars, n)`, a stored-type
  lookup rather than a decode.  The lint's reader test (`intermediate_rebuilt_per_call`:
  any loft call answering a scalar) is where a precision rule would go — e.g. a consumer
  that writes one of its other arguments is no reader.  Left as it is, not silenced.

## Watch for

- `cargo test --release` rebuilds `deps/libloft.rlib` in another feature flavour, after which
  every loft run from `target/release` prints the "libloft.rlib is STALE" warning — and
  `lib_process`'s twin test goes red on that stderr line alone.  Its cure (`cargo build
  --lib`) is undone by the next test build.  Run the test binary directly after a
  `cargo build --release --lib` to check it.  The warning itself is a candidate for the
  "not helpful" list: loft routes around the stale file, and the cure does not stick.

- A build can lose `target/release/deps/libsha2-*` (seen once here, beside a background
  test build); `loft --interpret` of anything that `use`s `selfhost/crt` then fails with
  `can't find crate for sha2`.  `cargo build --release --lib` restores it.
- The selfhost build prints only the known advice: too-many-parameters on
  `parse_function`/`field_vector`, trailing-boolean on `vector_build`, `api-redoes-per-field`
  on `int_range` and `rebind_witness`, and `view-copied` on `compound`, `match_expr`,
  `parse_block` and `place_root` (none of the four views is written through).
