## Open, in order

1. **Next to implement — the selfhost's setup stores are the Rust interpreter's.**  Not a
   question: [1b-interpreter.md](1b-interpreter.md) rule 5 (the same memory structures, no layout
   the Rust interpreter does not have) already says the report differs because the selfhost
   reinvented its setup.  `store_iter_scratch`, the census's one wrong, shows it.  Store `#0` is
   the stack at Rust's size, `#1` the constant store with Rust's content, read the way Rust reads
   it.  Today the program's hash prints as `#2 … bc:11566` beside an 8000 B
   stack and a 2 KB constant store on Rust, and as `#1 … bc:0` beside a 4 KB stack on the selfhost;
   the hash's own figures already agree.
   - **The Rust side.**  `State::new` (`src/state/mod.rs:957`) makes the stack store
     (`database_defined(1000)`, 1000 words) and then the constant store (`database(100)`,
     `CONST_STORE = 1`, `src/database/mod.rs:53`).  Code generation walks every `Function`
     definition in index order, skipping operators and placeholder instances
     (`src/compile.rs:190`), and `gen_text` (`src/state/codegen.rs:1141`) writes each text
     literal of 256 bytes or more into store 1 with `set_str`, emitting
     `OpConstStoreText(rec, 0)`; `string_from_const_store` (`src/state/text.rs:217`) reads it as
     a view of that record, no copy.  After code generation each vector constant gets a store of
     its own (`build_const_vectors`), and store 1 is locked.
   - **Order.**  `run::run` (`selfhost/src/run.loft:221`) and `cover/run_program.loft:48` call
     `consts::build` before `new_stack`, so a program with vector constants puts them below the
     stack.  Make it stack, constant store, vector constants.
   - **Stack.**  `STACK_START = 4096` bytes (`run.loft:146`).  `loft_crt_stack_new`
     (`selfhost/crt/shim/crt.c:111`) claims `(bytes + 15) / 8` words, so 7992 bytes is Rust's
     1000.  `stk_cap` should be the store's byte capacity, as `stack_cap_bytes` is, and growth
     Rust's rule — `grow_stack` (`src/state/mod.rs:3046`) grows to exactly `ceil(top / 8) + 1`
     words, where `run.loft:297` and `:471` double.
   - **Constant store, content.**  `consts.loft` makes it (`database(100)`: 792 bytes through
     `crt::database`), walks the definitions as `compile.rs:190` does, each body in code
     generation order, and writes every text literal of 256 bytes or more with a new shim routine
     that marshals `Store::set_str` (`loft_rstr_n` in `src/c/loft_reflect.h` is the C form), then
     locks it (`crt::lock_constant`) and releases it after the run with the others.  The walk
     needs `Data::is_placeholder_instance` ported, with `mentions_type_var`, `is_open_instance`
     and `is_type_var_placeholder` (`src/data.rs:11462`–`11729`); `binds.loft`'s
     `split_key_kind` already answers `is_instance`.
   - **Constant store, use.**  `NdText` (`selfhost/src/lower.loft:1173`) emits `PushText` over
     the lowering's own `texts` for every literal.  A literal of 256 bytes or more lowers to an op
     that carries its record, as `OpConstStoreText` does, and runs through a shim routine that
     reads it as `string_from_const_store` does (`loft_store_str`).  The lowering is lazy per
     definition, so the store is filled before the run and the lowering is handed the records.
   - **Verify.**  First that the walk's order is code generation's: a program with long literals

     untouched (`program_events` drops every store made before `M`).  A suite cell prints a long

## How to gate a batch (unchanged, plus)

Runner build → `cargo test --release --test selfhost` on the three backends → census (no program
lost) → `selfhost/compare/compare.py --layers out,alloc,leak,binds,slots` over every passing
program → a row in the record doc → commit.  After a compiler change rebuild the op-census loft
(`cargo build --release --features op-census --target-dir target/op-census --bin loft`); the
comparison now rebuilds its runner when a C runtime header changes.  Run suites with
`LOFT_SUITE_DIR=../loft-suite-91` — `make suite` defaults to `../loft-suite`.
