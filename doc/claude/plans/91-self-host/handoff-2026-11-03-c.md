## Open questions for the owner

- **loft#2391's other half needs a rule.**  `y = match c.tp { Opt { inner } => inner, _ =>
  c.tp }; c.tp = y` still answers neither variant.  At the write, `y`'s deps say only "views
  `c`" — the same as `e = v[0]; …; v[0] = e`, the identity the lost-write lint depends on — so
  the parser cannot stage it.  The scope pass could: copy such a view at its bind, as
  `(H-Materialise)` does for a reassigned local.  But `(B-Disturb)` names four things that end
  a place, and LOFT_DATA says *"overwriting a place is not ending it"* — neither says whether
  overwriting `c.tp` ends the place of a record `c.tp` OWNED.  Proposed fifth case: a whole
  record written into a place ends the places of the records the old value owned (the place
  itself stays, as now).
