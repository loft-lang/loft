## Also fixed: loft#2335

A collection literal whose part read its destination through a call (a place prefix handed to a
function, or an element read inside an argument) lost what the destination held.  Such parts are
now staged before the build (`snapshot_read_destination`); the elaborator's fresh-list workaround
is gone.

## Lessons for the port

- `(Col-Group)`: two keyed collections of the SAME element type in one struct are one record
  set.  Give every new counter/map in `Vars`/`El` its own element type (`LoopCount`,
  `UniqueCount`).
- The method that works stays: an Explore agent traces one small program through the Rust on
  both passes; port that path; refuse the rest by name; check with `elab_gate.py <files>`.
- When the elaborator's own data goes wrong, suspect a language defect before a porting error,
  and measure: three of today's four fixes were found that way.
