## Where it stands

- **The interpreter in loft** (`selfhost/src/`):
  - `lower.loft` lowers the closed IR of a program image to flat ops.
  - `run.loft` runs those ops with one stack per kind: int, float (single included), text, and
    `&text` as an index held on the int stack.
  - Covered so far: integer, float and text arithmetic; control flow; calls; texts; `&text`;
    the natives `assert` and `env_variable`; unary minus; `abs`; `len`, `size` and slices of a
    text; casts between the scalar kinds; a value entering a narrow integer; and **every
    format spec**, rendered by the C runtime through the `selfhost/crt` library.
- **Census** (`selfhost/cover/census.py`, writes `target/selfhost-census.tsv`): 1018 programs,
  **27 pass, 0 answer wrong, 0 crash**. Run it with `--loft target/debug/loft` while
  `target/release/loft` predates #2217's fix: `crt` passes booleans through `#c`. The rest
  are refused at store-held kinds: TyReference 663, TyVector 118, TyEnum 53, TyHash 33, tuples
  18. The scalar blockers left are natives (`n_now`, `n_store_memory`, 2 programs each).
  **S3, the store, is the blocker**, and it needs a paper design reviewed by the owner first.
- **Speed** (S1.4, `selfhost/bench/measure.py`, same box, best of 5): on the C backend, the
  loft interpreter is **20.3× (fib), 14.7× (mix) and 10.6× (collatz)** slower than the Rust
  interpreter. loft-13's C changes (`laptop-c-perf` 02096be4a, merged with 1b0029fe9) emit
  63 `static inline` functions against 11 but give the same times. The earlier 4.9–12.6× came
  from before the rebase, when the first C-perf join was on this branch. The cost is X21.

## Owner rulings this session (in the plan doc unless marked)

- Implement a construct when it can be done correctly and efficiently. Refuse it at compile
  time only when it certainly fails: it never ends, or it certainly exhausts its stores' memory.
- The semantic layer copies data rather than keep many stores alive; the code layer then
  reduces the copies. Warn on slow constructs, so that they stay out of libraries (@C155,
  `warning[tail-call-not-jumped]`).
- Keep the interpreter's loft code readable. Tricks for speed are the optimizing agent's job.
- Reuse the stdlib as much as possible, to limit IR discrepancies.
- Depend on the C runtime, never on loft's rustc side. The C backend becomes the canonical path.
- Start-up speed on par with the Rust interpreter is a goal, but not a blocker. Coverage comes
  first. SU1 means mapping the image copy-on-write, in the C runtime first (`loft_image.h`).
- **Newest ruling, not yet in the plan doc:** the C runtime routines are reached through the
  interpreter's own library, `selfhost/crt`, not through stdlib declarations. Only routines the
  C runtime already defines go there; everything else is loft code.
