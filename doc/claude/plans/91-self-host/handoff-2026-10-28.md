## Where it stands

- **The interpreter in loft** (`selfhost/src/`): `lower.loft` lowers the image's IR to flat
  ops, `run.loft` runs them with one stack per kind (int, float, text; `&text` as an index on the
  int stack).  It covers scalar arithmetic, control flow, calls, texts, `&text`, every format spec
  (through `selfhost/crt`, the C runtime's own formatting), the census's small operators, text
  slices, and the casts.  It does not hold store values yet: that is S3.
- **Census** (`python3 selfhost/cover/census.py --loft target/debug/loft`): 1018 programs,
  **27 pass, 0 wrong, 0 crash**.  The rest stop at store kinds: records 663, vectors 118,
  struct enums 53, hashes 33.
- **S3 (the store) is designed, decided and probed; the first slice is not built.**
  - The C runtime's own stores, reached through `crt` (owner).
  - A reference crosses `#c` as its three parts, `store, rec, pos` (owner).
  - The type table is derived in loft from the image (owner: drop the rustc dependency):
    `selfhost/src/types.loft`.
  - Probes P1–P5 all pass on `--interpret`, `--native` and `--native-c`:
    `selfhost/crt/tests/store.loft` (P1–P4) and `selfhost/tests/types.loft` (P5, the guard:
    the loft table equals the C generator's, row by row; a deliberately wrong `owns_heap`
    fails it by name).
- **Speed:** the loft interpreter is ~20× the Rust interpreter on fib.  Cause (loft-13's
  profile): `prog = progs[def]` copies a whole `Lowering` per call and return (register X21).
  Owner ruling: loft-13 builds 3c (a last-use move) and then 3b (a view copied only at the write
  that may hit it).  The run loop stays as written.
