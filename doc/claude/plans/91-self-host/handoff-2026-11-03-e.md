## Ported this session (elaborator)

- **A call that leaves out a defaulted parameter** (`sum(v)`, `init: T? = null`): the missing
  slots take the parameter's default from the image, or null for a nullable one
  (`add_defaults`' general arm).  Refused by name: a default that reads another parameter, a
  call in a default that needs hidden parameters of its own, a link, a hidden buffer.
- **`o.s += t` on a text field** (`assign_var_nr`'s text arm): a `_field_N` local takes the
  field's text before the value is read, the value is appended as it is (a formatted text is
  NOT flattened, unlike a local), and it is written back with `OpSetTextReplace`.  A non-text
  value is refused by name.

- **A formatted vector makes its `vector<T>` definition** (`check_vector`: the definition
  alone, at the end of the string literal), and the two gaps the programs it admitted met: a
  borrowing work ref takes no head initialisation and a text one `""`
  (`work_ref_takes_preamble`); a staged field value's temp is typed as its value (`exp_tp`).
- Text indexing (`OpTextCharacter`); a generic called through the instance the image holds
  (`i_<LEN><spelling>_<template>`, `sum(v)`), a generic with no instance refused by name; a
  constant empty comprehension builds no loop; `#width 32` refused by name (it was ignored);
  `[]` into a vector place (`OpClearVector`); a type shadowing a prelude name claims its stub
  first (`claim_declared_type_names`); an empty literal rebinding a keyed or vector local; an
  optional record's `!= null` is `OpNot(OpRefIsNull(…))`.
- `counts = []` then appends: pass 1 types the local `vector<unknown>`, an append refines the
  element, pass 2 builds the empty literal at it.  A comprehension in value position (the
  "Vector comprehension" block).  Not mirrored: `len([for …])` makes a stray
  `main_vector<unknown>` on Rust's first pass (`add_defaults` filling a vector buffer of a
  still-unknown element while it resolves `len`) — harmless, but a Rust wart worth a look.
- `?? []` (a vector subject with any default) is not ported at all — one program alone.
- A vector local returned at a narrow element (its content type, `byte` for `u8`); a
  comprehension into a declared narrow vector (`comprehension_into`'s defaulted `declared`).
- Links: `&` of a record or text local (`OpCreateStack`), a re-point `r = &q`, a whole record
  written through a link (`materialized_amp_field`), dispatch on a link's referent (loft#824's
  rule), a link passed where its referent is taken.  A keyed return is refused by name.
- Text fields in a record literal written into a place; a `τ?` field stored at `τ`'s layout; a
  field's struct filled on demand (Rust's numbering).  Refused by name: a no-parameter
  function whose body is one vector literal (`@FR-R-Const`'s constant twin — a port with
  several admission conditions), an append into a field of a `for` variable's element (Rust
  stages the item values there: which ones is the open question).
- Tuples: `__tuple<…>` (`Data::tuple_def`, scalar and text members), tuple vector literals,
  tuple types (`vector<(integer, text)>`), `for (a, b) in …` destructuring (the loop variable
  `__destructure_t_<line>_<col>`, members bound at the body's head or before a filter, `_` as
  `___N`).  Refused by name: a member reusing an earlier *plain* binding's spelling (Rust's
  `rebind_after_block` names it), `par`.  The elaborator and the `defs` report now start the
  program at the standard library image's end, so a synthetic definition registered first is
  compared.
- Refused by name (new): a mid-body `return` of a parameter beside a tail call the return
  buffer was renamed onto.  Rust keeps the parameter in the result's borrows on that path (the
  `Rename` road) and drops it on the `Bind` road (`1888-…`'s `mx_*`).  Porting it means the
  first pass knowing, before its rename, which road the tail takes — the drop now runs before
  `rename_ret_buffer`, and moving it after changed the road for `mx_p`.

- Generators: `iterator<T>` for a plain scalar, a text, a record, and a tuple of scalars and
  texts; `yield`, `yield from`, a `for` over a generator (destructuring a tuple one too),
  `next(g)`, `exhausted(g)`, and a handle passed to a function.  A yielded record that is not

- `parse_function` now reads `->` after `add_fn`, so a definition the result type makes
