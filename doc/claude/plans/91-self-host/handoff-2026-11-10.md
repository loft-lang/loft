## Diagnostics reviewed

- Fixed: the nullable-store warning on `NdLong { n: v } if v != null => v` (the match-guard clause
  above), and the two warnings every selfhost run printed (`lower.loft`, a long minimum is the
  `PushNull` it is).
- Helpful as they stand: `tail-call-not-jumped` (twice on this session's own code, cure exact);
  `never-read` on `tuple_match`'s `node`; `avoidable-copy` on a hint appended before its last read.
- **For the owner — a loop range as a divisor proof.**  In `for k in 1..n { s += x / n }` the body
  runs only where `1 <= k < n`, so `n >= 2`, yet `/ n` types `τ?` and the result draws the
  nullable-store warning (`R-Range/abs-is-ranged…` does).  No rule lets a loop range prove a
  divisor non-zero, as `(N-Index)` lets an active loop variable index.  Adding "the end of an
  active `lo..n` with a constant `lo >= 0` is non-zero in the body" changes inferred types in
  user programs, so it is a rule decision, not a fix.
- **For the owner — `loft --check` builds natively.**  `--help` says `--check` parses and
  compiles "without running" and "can be combined with --native to also verify rustc
  compilation", but native is the default mode, so a plain `--check` runs `rustc` (over ten
  minutes on `front/elab.loft`).  The library CI's "examples compile" step relies on `--check`;
  matching the help would drop the native compile coverage that step has been getting.
- `advice[view-copied]` on `match_expr`'s `result = b.tp` (el_expressions.loft): the copy is what
  the loop means, and a reduced probe draws nothing, so the ingredient that makes the scope pass
  count a write through `result` is not found yet.  Advice tier, so it gates nothing.
