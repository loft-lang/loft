## Libraries (`use`) — 2026-11-09

- **The use region** (`el_definitions::use_region`, `Parser::parse_file`'s use loop): a library
  is elaborated the first time a `use` names it, under the next source (`el::use_add`, aliases
  counted as Rust counts them), ahead of the importer's definitions — the recursion stands in
  for Rust's lexer switch plus `todo_files` resume.  The imports queue and apply at the region's
  end (`import_all`, `import_name`, `import_operators`, `bind_import` with `private`).  `pub`
  items publish what they declared (`publish`).  A library type is spelled `lib::Name` in keys
  (`declared_identity`); a consumer member of another spelling joins the library's set; a
  consumer method on a library type is keyed as on its own.
- **Qualified names**: `lib::f(…)` reaches the library's own definitions alone (`find_fn`'s
  `source`, `select(…, only:)`); `lib::Type` in a type and a struct literal
  (`el::qualified_def`).  Refused by name: `lib::name` as a value, a qualified run-time variant
  dispatch, a `use` inside a package (manifest resolution), `use self::`, `#package` files, a
  name-only library type, a cyclic `use`, a library found only by `LOFT_LIB`, `~/.loft/lib` or
  the registry.
- **Gate oracle fixed**: `LOFT_EMIT_PARSED` wrote an image even when the parse had errors (a
  library not found left stub definitions behind, exit 0), so gate E compared against a failed
  compile.  The image is now written only for a parse without error.  The gate passes a
  program's `@ARGS: --lib` directories to Rust and, as `LOFT_ELAB_LIB`, to the elaborator.
- Port rule met: `vector_of` makes `vector<T>`'s store type on the first pass where `T`
  already has one (an imported enum), ahead of `main_vector<T>` (`vector_rows`).

## Since the library slice

- `sort` of a vector of integers / floats / singles / texts lowers to `OpSortVector`
  (`sort_is_special`); a standard-library template's body comes with the image, so its
  instances fill from it (`has_body`); an instance is found program-wide (`any_source_nr`) and a
  library template's key carries `@<library>` (`instance_key`).
- **Forward type references**: a type named before its declaration takes a pass-1 stub of its
  source (`parse_type`), adopted by `struct` / `enum`; the file's end resolves the stubbed
  attributes and results (`el_schema::copy_unknown_fields`), and between the passes the stub is
  rewritten in every attribute and variable table (`resolve_adopted_stubs`).  On the first pass
  a field read, a field write and an argument typed by an unresolved stub answer untyped, as
  Rust's do.  A stub nothing adopts is refused (Rust reports it undefined).  A type whose
  fields reach it again (`A { b: B }`, `B { a: A? }`, a self-containing struct enum) is refused
  before layout: Rust lays that field out of line (`@FR-L-OutOfLine`), which the port does not
  carry; the port's `finish_type` recursed without bound on it.
- A text `if` bound to a local writes a format-string arm's value at the format block's own tail
  (`text_arm_into` recursing, as `push_text_arms_into` does), and the join borrows a record local
  whose text field an arm reads (`c.t` borrows `c`).

- **The run-time variant dispatcher** (`dynamic_dispatcher`, commit `dce128188`, disabled in
  `592ac02d7`) runs into a Rust compiler fault, filed as **loft#2443**: a pooled `vector<τ>`
  work buffer (R-WorkBuffer) is read after it was freed — `LOFT_POISON=1` on the interpreted
  elaborator faults at `rec=0xDEADBEEF` in a `main_vector<TypeT>` store; without it,
  `variant_positions` hands back `[13, 0]` for one argument.  Both backends; an extra `println`
  of the dispatcher's locals changes which locals are pooled and hides it.  The issue carries
  the in-context reproduction and what `loft introspect` shows (the dispatcher's vector locals
  become `select`'s pooled parameters; `select`'s `__ref_5` is lent to `variant_positions`
  twice, once through the dispatcher).  Next: reduce it from that IR (two frames lending one
  pooled buffer), fix it in the work-buffer pass, then re-enable the dispatcher (its code is
  in `dce128188`).
- **Narrowed (2026-11-09):** `LOFT_NO_LAZY_BUFFER=1` cures it (the pooling switches do not).
  A debug interpreter (`LOFT_POISON=1 LOFT_STRICT_STORES=1 --interpret`) names a use after
  free of an `Ex` in `parse_block`: `expression` was handed a NULL record buffer, minted the
  record in a store of its own, and `parse_block`'s statement-end release freed it while `x`
  was still read.  Trigger: wiring the ported `store_else` (in the tree, unwired) into
  `parse_block`.  Details on loft#2443.  Store-`else` is now wired through `statement()` (one
  binding of `x` in `parse_block`, no conditional rebind), and the dispatcher is back with the
  positions computed once in `select` and passed in — neither triggers it now.  The bug itself
  is NOT fixed: reproduce from `dce128188` (dispatcher) or `982d93e0a` with the conditional
  rebind of `x` restored.
- **Root-cause lead:** with the second rebind, the record-buffer reuse declines `__ref_10`, so
  `x` lives in `expression`'s own store and is released at statement end — while `l`, built by
  `splice(l, items)` from `match x.code { NdInsert { items } }`, still points into it.  The
  defect is that missing borrow (a value derived from a match binding into a record does not
  keep the record alive); reduce THAT shape (a record a callee answers in its own store, an
  `NdInsert`-like vector field matched out and spliced into an outer accumulator, the record
  released at statement end) and fix it there.
