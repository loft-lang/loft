## First thing next session — an open use-after-free (on main, both backends, not filed)

A `for` loop variable whose name a LATER local of the same function reuses becomes an owner:
pass 1 writes the later `a = mk(…)` into the loop's variable (`binding_ended` splits only where a
retype would be refused, and here the types are equal), its owned record strips the loop
variable's dep, and the loop frees the iterated store every pass.

    for a in def(e, d).attrs { … }   // `a` var 9: ref(A), OWNS — should be deps=[the vector]
    a = mk(fname);                   // var 15 on pass 2, but var 9 keeps pass 1's type

Repro (answers `ok`, but `LOFT_STRICT_STORES=1` reports the use after free):

```loft
struct A { n: text, k: integer }
struct D { attrs: vector<A>, name: text }
struct E { defs: vector<D>, log: vector<text> }
fn def(e: E, d: integer) -> D { e.defs[d]! }
fn mk(n: text) -> A { A { n: n, k: len(n) } }
fn add_fields(e: E, d: integer, names: vector<text>) {
  for fname in names {
    for a in def(e, d).attrs {
      if a.n == fname {
        e.log += ["dup {fname}"];
      }
    }
    a = mk(fname);
    e.defs[d].attrs += [a];
  }
}
fn main() {
  e = E { defs: [D { attrs: [], name: "d" }], log: [] };
  add_fields(e, 0, ["x", "yy", "x", "zzz"]);
  total = 0;
  for a in e.defs[0].attrs { total += a.k; }
  assert(len(e.defs[0].attrs) == 4 && total == 7 && len(e.log) == 1, "{len(e.defs[0].attrs)} {total} {e.log}");
  println("ok");
}
```

`LOFT_STRICT_STORES=1` names the use after free on
`--interpret` and `--native-c`, on main too; renaming the later local cures it.  It crashes the C
build of the elaborator on 60 corpus programs (`parse_struct`'s duplicate-field loop, then
`a = el::attribute(…)`).  Probably the same root as loft#2330 (a later same-named local's type
reaching a comprehension's variable).  To do: file it (`scripts/claim.py file`, sev:high,

later bind is a new binding on BOTH passes), suite cell under `rules/binding/B-Scope` or
`ownership/`, falsify receipt, then rerun `elab_gate.py`.

## How the work goes

- Port method: an Explore subagent traces the exact Rust path for ONE small program on both
  passes (file:line, branch taken, state changes, IR); port that path, refuse the rest by name;
  check with `python3 selfhost/front/elab_gate.py --loft target/release/loft <prog.loft>…`.
- The oracle side of one program: `LOFT_EMIT_PARSED=<x.store> target/release/loft prog.loft`,
  then `loft --interpret selfhost/compare/defs.loft <x.store> program` (run from `selfhost/`).
- A C-build crash of a runner: build with `--emit-c`, compile by hand with
  `-DLOFT_STRICT_STORES` or `-fsanitize=address -DLOFT_VERIFY` (link the `libcrt_shim_*.dylib`
  the `--native-c` build leaves beside it), and break on `loft_strict_use_after_free`.
