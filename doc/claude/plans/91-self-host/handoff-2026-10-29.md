## How to run the package tests on the native backends

`tests/selfhost.rs` runs them on the interpreter only.  For `--native`/`--native-c`, emit each
kernel's image, C and type table into a directory and point the same three variables at it
(`LOFT_SELFHOST_IMAGE`, `LOFT_SELFHOST_KERNELS`, `LOFT_SELFHOST_NOT_AN_IMAGE`), then
`loft test --native` / `--native-c` in `selfhost/` and `selfhost/crt/`.  The `.ctypes` file is
`c_type_table` of `tests/selfhost.rs` over the emitted C.

The `.cdflt` file is `c_default_images` of the C emitted with `LOFT_NO_COMPLETE_WRITE=1`.

## Box rules

- `/tmp` is a shared 7.5 GB tmpfs: point test scratch at `/var/tmp`
  (`TMPDIR=/var/tmp/loft-test-scratch-loft-91-self-host-probe`).
- `source scripts/sccache_env.sh` before any cargo build (`CARGO_INCREMENTAL=0`).
- A bare `loft` run is native; both-backend checks need `--interpret`.  A native run inside a
  package directory leaves a `.loft/` cache there.
- A change to `selfhost/crt/src/crt.loft` rebuilds the package's native glue with rustc
  against `target/debug/libloft.rlib`; when that rlib is stale, rustc answers `E0460 found
  possibly newer version of crate` — `cargo build --lib` refreshes it (~15 minutes here).
- A census writes a thousand program images; it now removes them, but check `df -h /` before
  a run.
- loft-13 announces timing windows: run no builds or tests until they say it is done.
- The language suite for this branch: a worktree of `../loft-suite` on branch `91-self-host`
  (`git -C ../loft-suite worktree add <dir> 91-self-host`), passed as `LOFT_SUITE_DIR`.  Never
  switch the shared `../loft-suite` checkout, which stays on `main`.
- Issues are filed with `scripts/claim.py file`, measured on installed main (6f31a726b).
