Two bars: against Python's `hello` (15–19 ms) the installed binary is AT the bar — the recheck measured 13 ms; against the bash original the stamp port was met on (a 12 ms `cat | sha256sum` pipeline) it is not, by a millisecond, which is why the probe's bar is 12.  The program cache is on for every binary since @C133 (`LOFT_NO_CACHE=1` is the cold reference, 87 ms here), so a from-source `target/release/loft` measures the same path as an installed one after its first run.


The native path's own cost, found 2026-10-20: a development build launched `rustc --version` on EVERY run — a cached native run and an `--interpret` run alike — about 15 ms, more than the rest of a warm start.  The source-keyed fast path's key was computed before the run mode was looked at, and it found the runtime rlib by asking the live rustc which of the `deps/` and uplifted copies it could read (loft#2033).  The key now hashes both candidates and is computed only where it is used (3a2dd6169): a cached `--native hello` 27.3 ms → 16.3 ms, `--interpret hello` 28.9 ms → 18.2 ms on the owner's box (a bare process launch 5.3 ms, the compiled `hello` alone 7.9 ms).  A release install never held both rlibs, so it never paid; what a cached native run still costs is two process launches — loft, then the program.  `LOFT_TIMING=1` now reports any rustc launch (`rustc_probe=`), and `tests/native_source_key.rs` pins that a warm hit and an interpreted run make none.


Where a warm `hello` goes, measured 2026-10-21 with timestamps from the parent's spawn to `main`, through each phase, to the `atexit` handler and the reap (interleaved against controls, so a loaded box hits every arm alike): **before `main`** a bare process plus ~2 ms of loft's own — the Security and CoreFoundation link `rustls-native-certs` needs (404 framework initialisers: 1.5 ms CPU, 1.7 ms wall, measured by a build without it) and the 24 MB image (a 20 MB C binary costs 1.6 ms over a small one); **inside `main`** the front end (bundle 2.2 ms, scopes 0.9), bytecode 1.0, the run, and the exit.  Two of those were waste and are gone (8600e0b6b): every run deep-copied the whole definition table to hand it to the interpreter (`IntoSharedData for &Data` is `Arc::new(self.clone())`; 0.68 ms of an EMPTY `main`) and freed it again at exit (0.3 ms); and the program manifest re-hashed the seven stdlib files its `stdk` line already pins (0.68 → 0.04 ms).  `main`→reaped 7.7 → 5.7 ms; CPU 23.4 → 21.6 ms against `f2bcfd112`, same load.  What is left is structural: bytecode and the scope pass are not in the bundle (@PLN11 M6, ~2 ms), the bundle is copied out of its map (2.2 ms, 1.6k page faults), and the framework link is an owner's call because it is how the keychain's trust settings reach a TLS-inspecting proxy (finding 006).  The recheck must run against the build under test (`scripts/script_recheck.sh --loft target/release/loft`): the installed `loft` here is 2026.8.0 and measures none of this.
