An element-first temp now depends on its element (`e2783eeae`, the drawing lock fix), so the
store verdicts see that it shares the element's store.  Where the shared store is safe, two of
them now decline more than they need to:

- **The C's `(R-Push)` in 12_drawing, 13 → 3** (with `R-PushFill`, `R-Header`, `R-Base` on both
  writers).  A held C push header writes by record number (`loft_ph_put*` via `loft_at`), so it
  survives a growth of the store; only raw addresses (`(R-RecPtr)`, `loft_win`'s `base`, rustc's
  held bases) do not.
- **`grid`'s inner window** (`c_emit`'s push-window pin, 11 → 10): the inner loop claims nothing
  else in the store, so the window was sound; the verdict should ask whether the loop claims in
  the shared store, not whether the store is shared.
