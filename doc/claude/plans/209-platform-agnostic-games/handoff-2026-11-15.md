difference found is the tolerance, written beside the guard with its cause.

render pass and a read-back.  The AppKit window and its events are in `gpu_gl/c/gl_base.h`
for an OpenGL context only; a Metal backend needs the same window with a `CAMetalLayer`, so
M3 (the host picks Metal on a Mac) is where that code gets one home for both.

one that depends on `gpu` cannot pass the library CI until `gpu` is in the registry.  The

`scripts/registry_maintain.sh --only gpu` (an agent's run of it was refused), and the backends
for a released loft that has @C164.

**How this branch reaches `main`:** through the joining stream's gather, not a PR of its own.

What the rows already say about the API:

- **Arrays of uniforms set by a formatted name** (`"uLights[{i}]"`, stage) are the hardest row
  for a uniform block bound by slot from a loft struct: the block needs fixed-length arrays.
- **Instance attributes are rebound per run with a byte offset** (stage's
  `instance_attrib(buffer, location, size, stride, base + offset)`): the vertex layout is part
  of the pipeline, the offset is part of the draw.
- **A texture is updated in place** (`atlas.put`, the game) and filtered nearest: both stay.
- **A render target is one colour texture, resized by replacing it** (stage's `scene`).
- **The window's own state calls** (`enable`, `blend`, `cull`, `depth_write`, `scissor`,
  `viewport`) are what a pipeline and a pass take over; scissor and viewport change inside a
  pass and stay calls.
- **Still to count**: graphics' tests `buffers.loft`, `texture.loft` and `state.loft` (the
  instanced, indexed, lines, points, `line_width`, `point_size`, `finish`, depth-texture and
  mipmap uses), `GroupMeshes`, dryopea's four programs, and the 41 gallery programs.
