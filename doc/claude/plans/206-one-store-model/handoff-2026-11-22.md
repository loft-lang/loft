## What the session learned

- The verify cannot compare a call that reaches a C function's own state (a generator, a
  handle counter): running it twice changes that state.  Such calls are made once and counted
  ("made without a comparison"), and the file's output is the comparison.
- A hosted unit is an OPEN unit (`Cx::open`): no value records, so an export keeps the
  signature the bridge calls.
- A `[c] shim` must be one image: the unit links the shim's shared library (the `CLibrary.name`
  the parse built), never its archive.
- `loft test` inside a package never adopts the package; only a consumer run does.

2. A census with it: every package of the five repositories (`git archive origin/main`
   exports, as in § Start here), one consumer per library (`use <lib>; fn main() {}`) run with
   `LOFT_LIB_BACKEND=c LOFT_HOSTED_VERIFY=1 --interpret --lib <roots>`: the declined count per
   reason across all libraries.  The earlier guess from signatures was 507 of 2,605 public
   functions (251 text, 173 vector, 83 tuple); measure it.
3. Then carry the largest reasons, one at a time, each with a guard in `tests/hosted_unit.rs`
   (falsified) and the library sweep (`hosted_suite.py`, `--prebuilt` too) after each:
   - **A text result** — the dispatcher takes a text answer through a destination
     (`text_dest_mode`, `bridge_text_dest`) or the self-stashed work buffer, a Rust `String` in a
     store cell (`extensions.rs`, the `Some(ArgT::Text)` arm).  The C unit cannot write a Rust
     `String`: carry it as `LibArg.text_ptr`/`text_len` (the unit's own text, valid until its
     next call) and let the dispatcher copy it into the destination, or add a host call that
     appends to it.  Text work buffers (`BridgeAttrKind::WorkText`) are the same question.
   - **A vector answer** — answered into the caller's hidden buffer as a record is
     (`HiddenDest`), its type through `loft_tp_out`; check what `hosted::bridge` declines and
     why (`"a vector answer"` comes from `ctype` of the result).
   - **A tuple** — the dispatcher already reads `sig.ret_leaves` (one slot per leaf): the bridge
     writes each leaf to `loft_r + i * LOFT_LA_SIZE`.
   - **An iterator** — needs the host's coroutine table (`HostTable::coroutines`, as the rustc
     artifact forwards them); likely last.
4. Keep each step's red condition: a library's suite answers differently adopted, or the
   verify stops at a call.
