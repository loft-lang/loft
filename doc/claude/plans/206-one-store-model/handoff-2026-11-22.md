## Start here

```sh

for r in core game graphics net world; do
  git -C ~/workspace/loft-libs-$r fetch -q origin main
  mkdir -p $SP/libs/loft-libs-$r && git -C ~/workspace/loft-libs-$r archive origin/main | tar -x -C $SP/libs/loft-libs-$r

L=""; for r in core game graphics net world; do L="$L --lib $SP/libs/loft-libs-$r"; done
python3 scripts/hosted_suite.py --jobs 6 --timeout 300 $L $(ls -d $SP/libs/loft-libs-*/*/ | sed 's|/$||')
```

work branches, and an adopted run writes `native-auto/` into the package.

## What the session learned

- The verify cannot compare a call that reaches a C function's own state (a generator, a
  handle counter): running it twice changes that state.  Such calls are made once and counted
  ("made without a comparison"), and the file's output is the comparison.
- A hosted unit is an OPEN unit (`Cx::open`): no value records, so an export keeps the
  signature the bridge calls.
- A `[c] shim` must be one image: the unit links the shim's shared library (the `CLibrary.name`
  the parse built), never its archive.
- `loft test` inside a package never adopts the package; only a consumer run does.
