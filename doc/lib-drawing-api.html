pub fn hair_brush(bw: integer, bh: integer, seed: integer, gap: float) -> vector<integer>

The built-in split-bristle footprint. Columns group into channels 1..3 px wide, each a bristle with its own value; a gap fraction are thin translucent strands that FADE OUT along the run (the broken parallel streaks a worn brush lays); the outermost columns are soft so the silhouette frays. Greyscale value × alpha — the stroke's colour ramp multiplies in at resolve time. @FR-Brush-Image — the built-in footprint.

pub fn load_brush(path: text, bname: text, period: float) -> Brush

An authored footprint from a PNG: rows along the stroke, columns across. bw == 0 when the file could not be read. period 0 means one row per canvas px — the image's own height.

pub fn grey(gl: float) -> integer

A grey level in 0..1 as an opaque colour, rounded HALF TO EVEN.

Python's round is half-to-even and draw.py uses it here, so fill=0.5 is 128 and not 127 — a difference of one level that no eye would find and a byte diff would.

pub fn read_points(s: text) -> PointList

\(\s*(n)\s*,\s*(n)\s*\)\s*(~?)\s*(?:@\s*(n))?, found repeatedly along the line.

Scanning for points rather than splitting the line is what lets the same grammar carry options: rgb=140,104,62 has no parentheses, so it is not a point, and no separator has to be agreed between the two.

pub fn circle_pts(cx: float, cy: float, r: float, n: integer, flat: float, pw: integer, ph: integer) -> vector<raster::Pt>

The outline of a Circle, as draw.py builds it: n segments round the centre with the FIRST point repeated at the end, so the polygon closes itself and Pillow adds no edge of its own.

flat squashes the vertical radius; the W/H factor keeps the circle round on non-square paper, since the coordinates are fractions of each axis.

pub fn smooth_applies(pts: const vector<raster::Pt>, flags: const vector<boolean>) -> boolean

Does this outline curve at all? Fewer than three points, or no ~, and the control points ARE the polyline — which is what keeps a plain Poly unchanged.

pub fn smooth_pts(pts: const vector<raster::Pt>, flags: const vector<boolean>, closed: boolean) -> vector<raster::Pt>

Expand control points to a dense polyline. @FR-Mark-Smooth

A point flagged ~ curves (its tangent is half the neighbour chord); a corner uses the segment chord, which makes that segment exactly straight. So one outline mixes straight runs and curves, and a segment between two corners is a line however many ~ the rest of the outline has.

pub fn smooth_vals(vals: const vector<float>, closed: boolean) -> vector<float>

The per-point widths carried across the same expansion, interpolated linearly.

pub fn parse_scene(src: text) -> Sketch

Did the scene come out whole — every line understood, every mark drawn, every check passing? This is what --once exits on.

pub fn render(sc: const Sketch) -> graphics::Canvas

Draw a parsed scene: at SUPERSAMPLEx, then resampled down with Lanczos.

A transparent background renders on transparent pixels so the resample anti-aliases edges against ALPHA rather than against white — which is what makes the result a sprite that can be composited over anything, with no colour-key hack. @FR-Raster-Transparent · @FR-Mark-Deposit (fills and strokes overwrite; only Lock composites, through brush).

pub struct Frond { fpts: vector<raster::Pt>, fwid: vector<float> }

One frond: a centreline in paper fractions and a width per point.

pub fn fronds(x1: float, y1: float, x2: float, y2: float, sp: const FrondSpec, pw: integer, ph: integer) -> vector<Frond>

A linear array of tapered strokes rooted along the spine (x1,y1)-(x2,y2). @FR-Seed-NonUniform

Every frond is the same template placed at u along the spine and tilted off the normal, then made NON-UNIFORM three ways at once: placement clumps on the seeded low-frequency field, length / width / angle ramp along the run and are then jittered per frond, and the ends FRAY. Zero all three and it is a comb.

⚠ mirror reuses the SAME sample on both sides — length, angle and width are drawn once, outside the side loop, and reflected. Drawing them per side would consume the hash twice as fast and desynchronise every frond after the first.

Built in PIXEL space and handed back in fractions, so the array stays correct on non-square paper.

pub fn seed_hash(hseed: integer, hidx: integer, hsalt: integer) -> float

A reproducible pseudo-random float in [-1, 1) from three small non-negative integers.

⚠ NOT a PRNG, and deliberately not the random package. draw.py says so in its own docstring — *"never random()/hash() (those break reproducible renders)"* — and the corpus is defined by THIS hash: swap in PCG-64 and every jittered frond moves, so the substitution fails the gate it was meant to help pass.

Three details are load-bearing. The masking is 32-bit throughout, and the widest product it forms (0xFFFFFFFF * 1274126177) is 5.47e18 — inside i64 by a hair, so this needs no widening but has none to spare. And the final divide is a REAL division: x / 0xFFFFFFFF in integer arithmetic is 0 for every input and would give a perfectly smooth, entirely wrong field. @FR-Seed-Hash

pub fn seed_wave(lseed: integer, lu: float) -> float

A smooth low-frequency wave over [0,1], two harmonics with seed-derived phases.

Smooth in u is the point: neighbouring fronds see nearby values, so they CLUMP and leave gaps. White noise would scatter them evenly, which reads as man-made — the opposite of what this is for. Periodic in u, which is what lets a brush footprint tile along a stroke without a seam. @FR-Seed-NonUniform — the field an array clumps on.

pub struct Pt { ptx: float, pty: float }

A point in canvas pixels, before Pillow truncates it to a whole pixel.

The truncation is (int) on a C double — toward ZERO, so -0.4 lands on 0 and not on -1. Keep coordinates fractional right up to the rasteriser and the port and the oracle round the same way.

pub fn pt(px: float, py: float) -> Pt

Build a point without spelling the field names.

pub fn round_up(ru_v: float) -> integer

ROUND_UP from Draw.c — half AWAY from zero.

Not floor(f + 0.5): the sign lives outside, so the negative side mirrors the positive one exactly (ROUND_UP(-0.5) is -1, not 0).

pub fn round_down(rd_v: float) -> integer

ROUND_DOWN from Draw.c — ceil(f - 0.5), mirrored about zero.

The mirroring is the whole subtlety: ROUND_DOWN(-0.45) is **0**, because the ceil runs on |f| - 0.5 and the sign is applied afterwards. Take the obvious ceil(-0.95) instead and a span that should end on column 0 ends on column -1, which clips away and draws nothing.

pub fn fill_poly(cv: graphics::Canvas, pts: const vector<Pt>, ink: integer)

Fill a polygon the way ImageDraw.polygon(pts, fill=…) does.

The outline closes itself only when the last point is not already the first — a circle handed in with its start repeated gets no extra edge, which is how draw.py passes one.

pub fn wide_line(cv: graphics::Canvas, wx0: float, wy0: float, wx1: float, wy1: float, ink: integer, wwidth: integer)

One thick segment, the way ImageDraw.line(…, width=w) draws it for w > 1.

Pillow does not stroke — it builds a four-cornered quad around the segment and fills that, with the two half-widths rounded APART (ROUND_UP one side, ROUND_DOWN the other) so an even width still lands on whole pixels. A polyline is therefore a series of independent quads with no joins, and the overlap at a bend is what rounds the corner.

pub fn thin_line(cv: graphics::Canvas, pts: const vector<Pt>, ink: integer)

line32 from Draw.c — Bresenham, and it stops one pixel SHORT of the end.

draw_lines puts that missing pixel back after the last segment, which is why this is a polyline call rather than a segment one: split it into segments and each one grows a pixel Pillow never drew.

pub fn read_number(s: text, i: integer) -> Scan

A regex ([-\d.]+) — a run of digits, dots and minus signs, read as a number.

The character class is what draw.py writes, so this is deliberately loose: the run is taken first and converted second, and a run that is not a number fails the scan rather than being silently read as zero.

pub fn read_unsigned(s: text, i: integer) -> Scan

A regex ([\d.]+) — digits and dots, no sign.

pub fn read_uint(s: text, i: integer) -> Scan

A regex (\d+) — digits only.

pub fn find_option(s: text, key: text) -> Scan

The first \b<key>\s*=\s* on the line, answering where its VALUE starts.

This is the shape every option regex in draw.py opens with, and the word-boundary is load-bearing rather than decorative: without it w= would also be found inside w2=, which is a different option with a different meaning. key must be lowercase; the match is not.

pub fn find_word_from(s: text, word: text, start: integer) -> Scan

The first occurrence of a lowercase word at or after start, ignoring case — a regex literal with no boundary condition, which is what Circle and Line open with.

The start is what makes a failed parse behave like re.search: a command whose first occurrence does not parse is retried from the NEXT one rather than given up on.
