pub fn form_read_name(t: text) -> text

The name a text was written with. It is NOT part of the model — Form has no name field — so a round trip carries it only if the caller carries it. Names are ONE WORD: the layout puts h0 in the third field, so a name with a space writes a text this reader refuses.

pub fn form_read(t: text) -> Form

Parse a canonical text back into a Form. Returns a 0-sided form if the text does not have the canonical shape — the caller checks, and the gate treats that as a refusal.

pub fn form_eq(a: Form, b: Form) -> boolean

Are two forms the same shape? Compares the model rather than the text, which is what makes form_eq(f, form_read(form_write(f))) a round-trip check and not a tautology.

pub fn head_norm(h: integer) -> integer

Normalise a heading to 0..11.

EVERY index of the table goes through here. A running heading is h0 + sum(turn) and the turns are -5..6, so it leaves 0..11 constantly — a 4-sided cycle turning 3 each time reaches h = 12 on its last side. Two things then go wrong SILENTLY if the raw value is used: in loft a negative index reads from the END of a vector instead of returning null, and an index at or past the length returns null rather than wrapping. Both hand back a plausible wrong answer, which is why this is the first function in the file.

pub fn head_step(h: integer) -> (integer, integer)

The step for heading h, as (dk, dm) in doubled coordinates.

Ordered counter-clockwise from +x: h = 0 is due east, and each step is +30 degrees. Even h are the edge neighbours, odd h the vertex directions.

pub fn head_n2_4(h: integer) -> integer

4 * the squared world length of the step — EDGE_N2_4 or VERTEX_N2_4, exactly.

pub fn head_is_edge(h: integer) -> boolean

An even heading is an edge-neighbour direction; an odd one points at a vertex.

pub fn rot60_k(k: integer, m: integer) -> integer

The exact 60-degree rotation on doubled coordinates (ROUNDTRIP.md §1, constraint X1).

Both halves stay integral because every lattice point satisfies k = m (mod 2): k's parity is r & 1 and m = 3r has the same parity. On the heading table this acts as h -> h + 2, which is what makes the six rotations of O a subgroup of the twelve headings.

pub fn rot60_m(k: integer, m: integer) -> integer

The m of the same 60-degree rotation rot60_k gives the k of. Rotate a step by walking both, and the result is still exactly on the lattice.

pub fn refl_k(k: integer) -> integer

The exact reflection (constraint X2). On the heading table this acts as h -> 6 - h.

pub fn refl_m(m: integer) -> integer

The m of the reflection — unchanged, since the mirror is about the m axis. Present so a caller reflects by walking the same pair it rotates by, rather than special-casing one.

pub fn head_of_step(dk: integer, dm: integer) -> integer

The heading whose step is (dk, dm), or -1 if no heading has that step. Used by the gate to check the table against hex_field's neighbours, and later by recovery.

pub struct Form

── LAW J — A STENCIL BOUNDARY IS A CLOSED TURTLE CYCLE (step S1) ───────────

A Form is a walk: start facing fm_h0, and for each side walk fm_len[i] steps in the current heading, then turn by fm_turn[i]. It is admissible only if it CLOSES, and that is two independent conditions:

sum(len_i * e(h_i)) = (0, 0) the walk returns to its start sum(turn_i) = 12 it turned through exactly one revolution

NEITHER IMPLIES THE OTHER, and the gate proves it both ways. The last turn happens AFTER the last side, so it cannot move the endpoint — a wrong final turn leaves the vector sum at (0,0) and is caught only by the turn total. Conversely a wrong LENGTH leaves the turn total at 12 and is caught only by the vector sum.

THE TURN TOTAL IS +12, NOT -12. A cycle walked the other way round is the same shape with turn total -12, so requiring +12 picks one spelling of the two — the canonical-form rule C3 (DESIGN.md §3) applied at its cheapest point, before anything is written down.

pub fn perp_k(_k: integer, m: integer) -> integer

── WHY A LATTICE POLYGON CANNOT BE A RECTANGLE (step S1, OD-11) ────────────

Two headings 90 degrees apart exist (0 and 3), so a turtle cycle CAN turn a right angle. What it cannot do is make both sides quantise the same way, and that is a property of the hex lattice rather than of this table:

the perpendicular of (k, m) is (-m, 3k) 3*k*(-m) + m*(3k) = 0 its 4*len^2 is 3m^2 + 9k^2 = 3 * (3k^2 + m^2) EXACTLY 3x the original

Any lattice vector along that perpendicular is an integer multiple of the primitive one, so its length is sqrt(3) * (a rational) times the original — never equal, because sqrt(3) is irrational. THERE IS NO SQUARE SUBLATTICE OF A HEXAGONAL LATTICE (a lattice cannot carry both 4-fold and 6-fold symmetry), so no choice of headings gives a rectangle whose two sides are counted in the same unit.

That is why housedraw's Plan is a CONTINUOUS rectangle rasterised centre-in-region, and why it — not a turtle cycle — is domain A's shape primitive. See DESIGN.md §10.4.

pub fn poly_holds(vk: vector<integer>, vm: vector<integer>,

Is (pk, pm) inside or ON the closed polygon? Exact integer arithmetic throughout: the on-edge test is a zero cross product, and the crossing test compares a cross product's SIGN rather than computing an intersection, so there is no division and no epsilon anywhere.

ON THE BOUNDARY COUNTS AS INSIDE, and that is the whole reason the closed forms come out integral: the turtle traces the centres of the boundary ring, so those cells ARE the shape.

pub fn form_fill(f: Form, cq: integer, cr: integer, cells: HexSet) -> integer

THE ROUTINE: fill a closed Form into cells, anchored so the walk starts at cell (cq, cr).

A NON-CLOSING FORM IS REFUSED, NOT PATCHED (the control). Law J is the admission test; a walk that does not return to its start bounds no region, and silently filling "what it would have enclosed" would invent a shape the author never wrote.

pub fn set_shoelace2(cells: HexSet) -> integer

TWICE THE SIGNED AREA of the set's boundary, in doubled (k,m) units — summed over every boundary edge directly, so it needs no loop tracing: the shoelace of a closed loop is the sum over its edges, and summing over all loops is summing over all edges.

hex_edge_corners(dir) gives the edge's two corners in the winding order that makes the outer boundary positive and an enclosed hole negative, which is what makes = 12 * cells a real check on enclosure and not just on count.

pub fn tri_cells(n: integer) -> integer

── THE CLOSED FORMS — predicted, not read off the fill ────────────────────

Each is the count of lattice points inside-or-on the shape in the CENTRE basis (spanned by one edge step and the next-but-one), so each is a plain combinatorial identity rather than a measurement:

triangle side n the lattice points of a right triangle (n+1)(n+2)/2 rhombus a x b a box in the centre basis, (a+1)(b+1) hexagon side n the hex region of radius n, 3n^2 + 3n + 1

pub fn boundary_branches(cells: HexSet) -> integer

PART 1b — pinches. crawler's tracer relies on a hex boundary never pinching at a vertex (each vertex touches exactly 3 mutually adjacent cells), verified there over 412 forms — a T2 claim, re-measured here as a gate rather than assumed.

PART 1c — how many separate closed loops the boundary forms. ONE means the region is a single simply-connected shape; TWO means it has a hole (the outer loop plus the hole's), which is I3's named failure. Label propagation over the edge graph — the edge count is small and this needs no auxiliary structure.

pub fn form_is_convex(f: Form) -> boolean

── A4 — LAW J IS NOT A SUFFICIENT ADMISSION RULE ──────────────────────────

Law J asks only that the walk CLOSES: Σ turn = 12 and the vector sum is zero. Rung A4 grew the space to unequal sides and REFLEX corners, and found law J admits two things it must not:

NON-SIMPLE walks — a repeated vertex, so the "polygon" crosses or touches itself and has no well-defined inside. NON-CONVEX forms — which VIOLATE LAW F. Measured over the 70 simple non-convex 4-sided forms: 62 of 70 at unit scale, and still 36 of 70 grown five times, draw a field that some OTHER form also draws. draw is not injective there, so no recovery — hull, tracing, or anything else — can tell them apart. Scaling shrinks the failure but never removes it.

THAT IS A MODEL-SPACE LIMIT, NOT A METHOD LIMIT, and it is why the fix is at the DOORSTEP (K-FIT): the editor refuses a non-convex stencil at authoring time rather than letting one be drawn and fail to come back. DESIGN.md §5.2 — a restriction the census finds is a fact to record, not a defect to engineer away.

A convex form is exactly one whose turns are all POSITIVE: every exterior angle turning the same way, summing to one revolution. A turn of 0 is a straight join, which is a re-spelling of a longer side rather than a corner, so it is refused too.

pub fn form_is_simple(f: Form) -> boolean

pub struct Plan

── the plan: a rectangle in its own frame ──────────────────────────────────

pub fn plan_new(cq: integer, cr: integer, wid: integer, dep: integer,

Place a form in the world: which cell it is centred on, how wide and deep, which of the six exact rotations, and whether it is mirrored. The Plan is the frame and the Form is the shape — keeping them apart is what lets one shape be placed many times.

pub fn plan_flip(p: Plan) -> Plan

A flip toggles the chirality and NOTHING else — no side remapping, no t -> 1-t. If an implementation finds itself remapping, the frame rule above is wrong somewhere.

pub fn plan_hw(p: Plan) -> float

Half the plan's width in world units — the extent a caller needs for a bound or a hit test, without reconstructing the frame.

pub fn plan_hd(p: Plan) -> float

Half the plan's depth in world units, the companion of plan_hw.

pub fn plan_to_world(p: Plan, lu: float, lv: float) -> (float, float)

A point in the plan's own frame, expressed in the world. The rotations are the six exact lattice ones, so this and plan_to_local invert each other rather than drifting.

pub fn plan_to_local(p: Plan, px: float, py: float) -> (float, float)

A world point expressed in the plan's frame — the inverse of plan_to_world, and how a click or a probe is asked "where is this ON the plan?".

pub fn plan_side_point(p: Plan, side: integer, t: float) -> (float, float)

A point a fraction t along one side of the plan, in world coordinates. Use it to place a door, a label or a joint without computing the side's endpoints yourself.

pub fn plan_side_normal(p: Plan, side: integer) -> (float, float)

Outward, unit — taken from the MASSING (centre -> side midpoint), never from the endpoint order. Reading it off B - A lets a broken endpoint rule supply its own definition of outward, and the facade gate can then never fire.
